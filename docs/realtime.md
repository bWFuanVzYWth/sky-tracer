# 实时方案与压缩取舍

当前方案以交互性能为主要目标，允许轻微、平滑的质量退化。它独立求解多散射，不需要部署 21 GB 的参考 LUT；参考烘焙器用于离线拟合、诊断和研究。

## 按变化频率分配工作

|发生变化|需要重算的内容|
|---|---|
|启动、大气、反照率、求解配置|光学厚度与四维各向异性多散射源|
|太阳高度、观察海拔|当前观察者的 SkyView；含单散射和多散射积分|
|相机方向、太阳方位、窗口尺寸|投影与显示，不重求整个介质|
|所有输入相同|复用已有屏幕结果|

四维多散射源描述“此处向该方向散射进来的间接光”。运行时沿视线积分直接单散射及该源项，得到观察者天空。太阳照明采用平行光，直接可见太阳盘独立显示；这不等于天空只剩一个像素的太阳。这个近似已经作为性能/质量取舍接受，有限太阳盘仍保留在参考求解器中。

固定介质下，变化太阳位置只是在已有状态表中查询。若每次拖太阳都重算多散射，首先应检查缓存失效条件。只把逐像素积分减少到四波长仍不够：SkyView 避免了每个屏幕像素每帧做 96 步积分。

## 当前稳定分配

精确配置以 [`balanced.json`](../crates/sky-realtime/configs/balanced.json) 和 `Config::balanced()` 为准；二者有一致性测试。

|资源或工作|默认设置|
|---|---|
|光谱|450、510、580、650 nm，四通道 f32 输运|
|多散射源状态|40 高度 × 160 太阳节点 × 20 相位 × 12 绕轴节点|
|启动入射积分|3 个方向图表，各 32×16 节点|
|启动路径积分、迭代|64 步，8 轮|
|光学厚度|128×512 RGBA16F，256 积分步|
|SkyView|256² RGBA32F，log Rec.2020|
|运行时路径积分|96 步|
|临时高度批大小|4|
|常驻载荷 / 求解峰值载荷|7.910 MiB / 44.194 MiB|

高度超过 35 km 后，当前介质只剩 Rayleigh 散射；它对出射方向的依赖可用精确二次型表示，每状态五个 RGBA32F texel。这里没有把任意气溶胶场强行截成低阶球谐。改变高空介质时，需要重新审查这个前提。

低空源项采用归一化后 f16 存储，求解和累积仍用 f32。方向、相位索引和同高度系数尽量复用。高度批处理只改变调度：每批读取同一轮旧场，写入新场的不同行，不把介质切成独立求解层；地面边界每轮只更新一次。整高度与 2/4/8 高度批在已测 43 视图上逐位相同。

SkyView 没有改成 f16：只省 0.5 MiB，却曾带来约 0.82% 的最大场景 P95 变化。也没有保留首阶缓存、材料边界切步、太阳阴影切步和高低空两套方位求积；实测收益不足以补偿复杂度。保留收益明确的反射对称、固定系数、重要方向图表及连续高度集中步进。

## 性能和质量分别看

以下为 RTX 4090 / Vulkan、512×384 输出的既有测量。太阳更新计时含显示 pass、不含初始化与回读，4 帧预热、64 帧测量，三个交替轮次取中位数。它们不是其他显卡或 4K 输出的保证。

|工作负载|旧 UE8 实现|当前实时|
|---|---:|---:|
|正午太阳变化|0.529 ms|0.239 ms|
|夕阳太阳变化|0.709 ms|0.269 ms|
|蓝调太阳变化|0.713 ms|0.254 ms|
|仅相机旋转|0.0092 ms|0.0123–0.0133 ms|
|输入不变|0.0092 ms|0.0051 ms|
|介质预计算|约 64.4 ms|约 393 ms|
|常驻表载荷|0.906 MiB，另有 0.5 MiB 空气透视纹理|7.910 MiB|

预计算时间为提交、执行和等待的墙钟时间，不含设备与管线创建；当前值来自六次测量。旧方案使用低维各向同性多散射，启动更快、表更小；当前为更高维的方向性付出一次性成本。资源数字不含驱动、输出目标、交换链和 UI，不能视为整个进程显存上限。

对冻结 41 波段参考，只统计天空像素并排除太阳盘，线性 Rec.2020 相对差的图像 P95 如下。旧实现包含光谱、介质和积分等多项不同，不能把结果全部归因于某一优化。

|场景|旧 UE8|当前实时|
|---|---:|---:|
|正午太阳附近|6.50%|0.62%|
|正午地平线|8.53%|0.91%|
|夕阳|39.00%|2.17%|
|蓝调向阳 / 背阳|50.22% / 47.98%|2.12% / 1.37%|
|12 km 暮光|50.19%|5.46%|
|30 km 地影|94.71%|4.09%|

旧实现把大气外观察者钳到大气顶附近，不能公平参与太空几何排名。当前支持真实太空入口查询，但完整图像对冻结参考的 108 km 薄边缘、400 km 暮光 P95 仍约 **30% / 16%**。这部分差异尚未充分归因，不能称为已解决。

以更密的四波长诊断解检查当前数值预算，425 个标准介质视图再加 112 个四倍气溶胶视图，共 537 个组合。先取各图 P95，再取集合最坏值：一般/高空约 2.418%，近地掠角 1.163%，四倍气溶胶掠角 4.103%。这些是有偏解之间的差异，不是上述光谱参考误差。

SkyView 单独对同配置逐像素积分的最坏场景 P95：一般/高空 1.121%，近地掠角约 0.298%；薄边缘仍有最高约 12.5% 的单像素尾部。说明不能只看平均数或把所有剩余误差都归到光谱。

## 有限线段与体积效果

实时核心提供四波长的有限段 L/T，验证包含：

```text
L(a,b) = L(a,c) + T(a,c) L(c,b)
T(a,b) = T(a,c) T(c,b)
```

六个实际 GPU 场景的组合检查最大辐亮度相对差约 0.00219%，透射率绝对差约 `5.25e−6`。这是接口内部一致性，不是所有雾场景的质量认证。

当前尚未完成场景遮挡、froxel 缓存或 RGB 背景到四通道光谱的重建。不能把天空 RGB LUT 直接当成通用体积照明场；线段位置、长度、背景谱和遮挡都会影响结果。

## 固定大气还能怎样压缩

完整参考允许在 CPU 上大量合成数据，再试生产表示。必须分清参考自身误差、离线表示误差和实时解码代价。下面的数字是既有本项目实验，不是通用压缩率承诺。

|方法|已知收益|主要问题与结论|
|---|---|---|
|全节点 RGB + 自定义整数打包|约 1.543 GB 降至 469.75 MB；纯编码非节点查询 P99 约 0.01284%|保留 f32 指数范围、11 位尾数和重复块；适合参考显示，远超实时预算|
|直接 BC6H|实验布局估算约 186.86 MB，含缩放与太阳表|随机块试验的“每块最差点”P95 约 9.51%，不能当作整图 P95；太阳峰、黑区和强梯度困难，未生成全量生产包|
|联合 Tensor Train + 大气顶边界|预算约 15.70 MB，保留原节点位置；原查询集 P95/P99 约 1.48%/2.46%|更广的高空留出集仍有暗部和地影失败；CPU 原型没有实时 GPU 吞吐结论|
|直接 SH 压完整辐亮度|17 阶估算约 15.28 MiB，未含辅助表|无法有效表达太阳峰与地影边界；即使 64 阶约 190 MiB，太阳附近仍差，不采用|
|实时单散射 + 四维多散射源|常驻 7.910 MiB，不加载完整参考|要做启动求解和 SkyView 更新；目前采用|

BC6H 适合局部平滑 HDR 数据，可以继续考虑归一化后的主体或残差；不能只用每 texel 位数推断总预算，缩放、补丁、索引和缓存都要计算。自定义打包保留动态范围，但随机读取和原有非线性插值有成本。当前没有两者等质量 GPU 解码速度的完整比较。

联合低秩利用四维相关性，比各切片独立压缩更有潜力。已有 TT 使用 `(高度,太阳)` 联合因子，再分解观察位置和相位/RGB；秩和维度顺序显著影响结果。原有 log/PCHIP 插值是非线性的，先插值因子再相乘不等价于先恢复节点再插值，不能无验证地替换。全球均方能量拟合还容易牺牲极暗大气，需要分区和亮度权重。

另一个参考是 [Prague Sky Model](https://github.com/PetrVevoda/pragueskymodel)，对应 Wilkie 等 2021 年的辐亮度/衰减拟合模型与后续光谱扩展。官方完整数据约 2.2 GB，还覆盖能见度、反照率和偏振；地面版约 103 MB。其公布的高度/太阳范围也不同，不能直接用文件体积估计我们“固定介质、任意太空海拔”的压缩率。可以借鉴拟合表示和衰减建模，当前未移植其实现，也没有同设备实时性能结论。

后续值得优先解决的是高空薄光照区的入射积分，以及局部插值尾部。若重启全辐亮度压缩研究，应先隔离前向峰和大气顶边界，再比较真实查询成本；不要继续单纯提高全球球谐阶数。
