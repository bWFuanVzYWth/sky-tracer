# 实时方案与压缩取舍

当前方案以交互性能为主要目标，允许轻微、平滑的质量退化。它独立求解多散射，不需要部署约 19 GB 的参考 LUT；参考烘焙器用于离线拟合、诊断和研究。

## 按变化频率分配工作

|发生变化|需要重算的内容|
|---|---|
|启动、大气、反照率、求解配置|光学厚度与四维各向异性多散射源|
|太阳高度、观察海拔|当前观察者的 SkyView；含单散射和多散射积分|
|相机方向、太阳方位、窗口尺寸|投影与显示，不重求整个介质|
|所有输入相同|复用已有屏幕结果|

四维多散射源描述“此处向该方向散射进来的间接光”。运行时沿视线积分直接单散射及该源项，得到观察者天空。太阳照明采用平行光，直接可见太阳盘独立显示；这不等于天空只剩一个像素的太阳。这个近似已经作为性能/质量取舍接受，有限太阳盘仍保留在参考求解器中。

固定介质下，变化太阳位置只是在已有状态表中查询。若每次拖太阳都重算多散射，首先应检查缓存失效条件。只把逐像素积分减少到四波长仍不够：SkyView 避免了每个屏幕像素每帧做路径积分。太阳高度连续变化时，SkyView 本身仍须每帧更新，这项成本计入整帧优化。

## 当前稳定分配

启动与 LUT 配置以 [`balanced.json`](../crates/sky-realtime/configs/balanced.json) 和 `Config::balanced()` 为准，二者有一致性测试。运行时步数由实时核心的 `DEFAULT_RUNTIME_STEPS` 统一提供给 renderer、demo 和 audit CLI。

|资源或工作|默认设置|
|---|---|
|光谱|450、510、580、650 nm，四通道 f32 输运|
|多散射源状态|40 高度 × 160 太阳节点 × 20 相位 × 12 绕轴节点|
|启动入射积分|3 个方向图表，各 32×16 节点|
|启动路径积分、迭代|64 步，8 轮|
|光学厚度|128×512 RGBA16F，256 积分步|
|SkyView|256² RGBA32F，log Rec.2020|
|运行时路径积分|64 步；`DEFAULT_RUNTIME_STEPS`，与启动积分分别设置|
|临时高度批大小|4|
|常驻载荷 / 求解峰值载荷|7.910 MiB / 44.194 MiB|

高度超过 35 km 后，当前介质只剩 Rayleigh 散射；它对出射方向的依赖可用精确二次型表示，每状态五个 RGBA32F texel。这里没有把任意气溶胶场强行截成低阶球谐。改变高空介质时，需要重新审查这个前提。

低空源项采用归一化后 f16 存储，求解和累积仍用 f32。方向、相位索引和同高度系数尽量复用。高度批处理只改变调度：每批读取同一轮旧场，写入新场的不同行，不把介质切成独立求解层；地面边界每轮只更新一次。整高度与 2/4/8 高度批在已测 43 视图上逐位相同。

散射源卷积跳过当前高度上四个波长散射系数全为零的气溶胶组分，保留有效组分的求积节点和累加顺序。`skip_inactive_species=true` 是默认配置；`false` 可复现优化前的工作量。在 43 个标准视图、22 个新增视图及 112 个四倍气溶胶掠角视图上，逐像素 source / SkyView、源场和光学厚度导出均逐位一致。每条射线缓存相位坐标也做过同样的等价性检查，但收益不足以稳定改善默认 SkyView 更新，`cache_phase_coordinate` 默认关闭，保留作实验消融。

SkyView 没有改成 f16：只省 0.5 MiB，却曾带来约 0.82% 的最大场景 P95 变化。也没有保留首阶缓存、材料边界切步、太阳阴影切步和高低空两套方位求积；实测收益不足以补偿复杂度。保留收益明确的反射对称、固定系数、重要方向图表及连续高度集中步进。

## 性能和质量分别看

当前优化目标是固定大气、太阳连续移动时的 **1920×1080 完整纯天空帧**。新 `sky-audit profile` 使用真实逐帧太阳位置，计入 SkyView 更新、全分辨率投影、可见太阳盘和 demo 原有的色调映射/显示 shader。RTX 4090 / Vulkan / 616.56，四条太阳高度与方位连续变化轨迹，每轮 8 帧预热、120 帧测量、3 轮；每条轨迹先取轮次中位数，再对四条等权平均。旧 96 步配置在新默认前后各测一次作为控制。

|完整帧或阶段|256² / 96 步基线|256² / 64 步默认|减少|
|---|---:|---:|---:|
|完整 GPU 帧|0.298688 ms|0.220416 ms|26.21%|
|CPU 编码、提交与等待 GPU 完成的整帧墙钟|0.490250 ms|0.415100 ms|15.33%|
|其中 SkyView GPU 更新|0.244400 ms|0.166272 ms|31.97%|
|1080p 投影|0.017220 ms|0.017216 ms|基本不变|
|显示 pass|0.023552 ms|0.023552 ms|不变|

整帧墙钟包含约 0.115 ms 的 CPU 观察者坐标构造、参数上传和驱动调度；不能把 GPU 的 26% 降幅直接声称为 CPU/GPU 整体也降低 26%。query resolve/copy 与图像回读在计时外完成并等待，逐帧提交防止 uniform 被下一帧覆盖。测量不含设备/管线创建、固定介质启动求解、UI、交换链与 vsync。仅太阳方位变化复用 SkyView，两边完整 GPU 都约 0.053248 ms。原始结果见本机 `out/realtime_1080p_final_v1/comparison.json`，复现入口见[研究指南](research.md)。

预算实验保留现有映射、四波长权重和源场网格。比较了 SkyView 224²/192²、运行时 80/72/64 步及组合。192²/72 步的整帧 GPU 降幅约 27.6%，只比保留 256²/64 步多约 1 个百分点，但 1080p 轨道薄边缘出现约 14.5% 的线性单像素差、实际显示最高 9 LSB；224²/72 步最高 5 LSB。因此默认保留 256² 的采样网格，只减少积分步数。

64 步验收包含 8 条轨迹 × 65 帧的连续太阳序列、14 个 1080p 敏感/最坏姿态，以及 43 个标准、22 个新增和 6 个四倍气溶胶固定相机回归，分别导出 source / sky，两模式全部有限。相对旧 96 步，三组固定相机的 SkyView 最坏图像 P95 分别约 1.327%/1.323%/1.069%；连续序列亮天空最坏图像 P95/P99 约 1.93%/3.82%；14 个高清画面的最坏 P95/P99/最大值约 2.445%/4.824%/6.558%，集中在薄边缘。实际高清显示全像素差最多 2 LSB，1:1 裁切未见新的明显粗条带或圆环；连续显示误差的一阶/二阶残差最大 3/5 LSB。这些检查支持轻微、平滑的质量取舍，不是对所有太阳轨迹的无伪影保证，也不消除已有高空模型误差。72 步为更保守的显式 `--steps 72` 备选；其高清显示最大 1 LSB。

CPU 坐标构造也做了独立剖析。缓存 JSON 系数只省不到 1 微秒；CDF 预计算或提前结束已饱和的二分搜索在常见视图只省约 5–10 微秒，未增加生产实现复杂度。该轮整帧收益来自已经测量并验收的积分预算。

## 教师驱动的 SkyView 节点分配

在上述 64 步预算上，使用 v7 教师的全部 41 波段导出 800,760 个密集方向查询，按物理海拔/太阳姿态分开训练和验证。只重新拟合现有 softsign CDF 的 `low/upper/space` 权重与宽度；运行时公式、源场坐标、地面映射、四波长与积分步数均保留。默认采用新的 256² 映射，不增加 LUT 字节数或 shader 分支。教师垂直插值留出 P99 从 0.8681% 降至 0.7437%，RMS 从 0.3367% 降至 0.2377%；这是单独的插值实验，不能当作物理模型误差。

同时，当整个相机视锥都在几何地平线以上时，`skip_unused_ground=true` 跳过 SkyView 中未被读取的地面 chart 和对应 CPU 节点构造。相机转向地面会先补全地面区域再投影；极远距离或接近切线时保守更新完整表。源场、纹理尺寸和常驻载荷不变。170 张原固定回归图与完整更新逐位相同，GPU 缓存失效检查覆盖太阳改变、地面出现、返回天空和太空视图。

同一 RTX 4090 / Vulkan、四条连续太阳轨迹、每条 120 帧 × 3 轮的完整 1080p 新测量如下。测量范围与上节相同，包含 SkyView、投影和显示；墙钟包含 CPU 构造、提交与 GPU 等待，排除 timer/image 回读、初始化、UI 和 vsync。

|完整帧|旧映射 / 256² / 64 步|新映射 + 地面裁剪 / 256² / 64 步|减少|
|---|---:|---:|---:|
|GPU|0.219904 ms|0.199680 ms|9.20%|
|CPU 编码、提交与等待 GPU 完成的墙钟|0.409760 ms|0.353000 ms|13.85%|

更换映射本身成本基本相同。地面裁剪单独省 9.08% GPU / 13.98% 墙钟；拟合 224² 候选在裁剪后只再省 2.69% GPU，额外 22 场景插值尾部退化，未采用。当前默认仍为 256² / 64 步 / 7.910 MiB。

实际 GPU 的 SkyView 与同预算逐像素积分相比，额外 22 场景的最坏图像 P95/P99 为 0.877%/1.674% → 0.479%/1.193%；14 个高清敏感姿态为 2.697%/5.885% → 2.362%/5.257%。43 个标准姿态 P95 改善，但 P99 从 0.810% 小幅升到 0.903%，并非各处都更优。source / optical 载荷和全部逐像素 source 图逐位相同。22 个额外场景中少数姿态与本次密集训练重合，不能把整组称作本轮盲测。

除既有 520 帧回归，还检查了完全独立的六条太阳轨迹共 390 帧，海拔 0.08/1.7/18/75/135/600 km，未用于拟合或候选选择。相对旧映射，亮天空最坏图像 P95/P99 为 0.545%/3.093%；实际 SDR 每帧与一阶时间残差的 P99 均不超过 1 LSB。13/14 个高清画面全像素差最多 1 LSB；轨道薄边缘例外，最大 9 LSB 出现在 6 个像素，198/2,073,600 个像素超过 2 LSB。独立轨道运动序列的一阶残差差值最高 13 LSB，集中在三行薄边缘；代表像素该步旧映射实际变化 +7，新映射 −6。五帧裁切未见新的宏观条带，原有薄边缘的细微采样起伏仍存在，不保证每个像素平滑单调。上节全像素最多 2 LSB 仅指旧映射下 96→64 步的预算对比，不适用于此次坐标变更。

原始静态/完整成本/运动报告分别在本机 `out/sky_mapping_gpu_static_v7`、`out/sky_mapping_gpu_cost_v7`、`out/sky_mapping_gpu_holdout_v7`；综合结论与实际显示图集在 `out/sky_mapping_gpu_summary_v7_final`。合入后未传 `--mapping/config/steps` 的默认输出，14 个高清 HDR/SDR 均与验收候选逐位相同；新增 GPU 检查覆盖 72² 表的 workgroup 填充行与地面出现，结果在 `out/sky_default_mapping_final_v7`。[研究指南](research.md) 提供冻结输入、CPU 重拟合及串行 GPU 审查命令。此次改进不消除已有的高空模型误差，也没有改变教师自身极暗暮光的收敛限制。

新教师九个 32×16 诊断图中，预算调整前（96 步）的 SkyView P95：正午约 0.41% / 0.88%，夕阳约 2.00%，蓝调向阳 / 背阳约 1.99% / 1.29%，12 km 暮光约 4.83%，30 km 地影约 3.84%。高空薄边缘 / 轨道暮光仍约 30.28% / 17.53%；更密的四波长诊断解没有消除它们。这些旧视觉姿态和低分辨率图不属于新的盲测，不能替代薄边缘细节检查。

旧实现把大气外观察者钳到大气顶附近，不能公平参与太空几何排名。当前支持真实太空入口查询，但完整图像对冻结参考的 108 km 薄边缘、400 km 暮光 P95 仍约 **30% / 16%**。这部分差异尚未充分归因，不能称为已解决。

以更密的四波长诊断解检查当前数值预算，425 个标准介质视图再加 112 个四倍气溶胶视图，共 537 个组合。先取各图 P95，再取集合最坏值：一般/高空约 2.418%，近地掠角 1.163%，四倍气溶胶掠角 4.103%。这些是有偏解之间的差异，不是上述光谱参考误差。

## 有限线段与体积效果

实时核心提供四波长的有限段 L/T，验证包含：

```text
L(a,b) = L(a,c) + T(a,c) L(c,b)
T(a,b) = T(a,c) T(c,b)
```

六个实际 GPU 场景的组合检查最大辐亮度相对差约 0.00219%，透射率绝对差约 `5.25e−6`。这是接口内部一致性，不是所有雾场景的质量认证。

当前尚未完成场景遮挡、froxel 缓存或 RGB 背景到四通道光谱的重建。不能把天空 RGB LUT 直接当成通用体积照明场；线段位置、长度、背景谱和遮挡都会影响结果。

## 固定大气还能怎样压缩

完整参考允许在 CPU 上大量合成数据，再试生产表示。必须分清参考自身误差、离线表示误差和实时解码代价。下面的数字是既有本项目实验，不是通用压缩率承诺。

|方法|已知收益|主要问题与结论|
|---|---|---|
|全节点 RGB + 自定义整数打包|约 1.543 GB 降至 469.75 MB；纯编码非节点查询 P99 约 0.01284%|保留 f32 指数范围、11 位尾数和重复块；适合参考显示，远超实时预算|
|直接 BC6H|实验布局估算约 186.86 MB，含缩放与太阳表|随机块试验的“每块最差点”P95 约 9.51%，不能当作整图 P95；太阳峰、黑区和强梯度困难，未生成全量生产包|
|联合 Tensor Train + 大气顶边界|预算约 15.70 MB，保留原节点位置；原查询集 P95/P99 约 1.48%/2.46%|更广的高空留出集仍有暗部和地影失败；CPU 原型没有实时 GPU 吞吐结论|
|直接 SH 压完整辐亮度|17 阶估算约 15.28 MiB，未含辅助表|无法有效表达太阳峰与地影边界；即使 64 阶约 190 MiB，太阳附近仍差，不采用|
|实时单散射 + 四维多散射源|常驻 7.910 MiB，不加载完整参考|要做启动求解和 SkyView 更新；目前采用|

BC6H 适合局部平滑 HDR 数据，可以继续考虑归一化后的主体或残差；不能只用每 texel 位数推断总预算，缩放、补丁、索引和缓存都要计算。自定义打包保留动态范围，但随机读取和原有非线性插值有成本。当前没有两者等质量 GPU 解码速度的完整比较。

联合低秩利用四维相关性，比各切片独立压缩更有潜力。已有 TT 使用 `(高度,太阳)` 联合因子，再分解观察位置和相位/RGB；秩和维度顺序显著影响结果。原有 log/PCHIP 插值是非线性的，先插值因子再相乘不等价于先恢复节点再插值，不能无验证地替换。全球均方能量拟合还容易牺牲极暗大气，需要分区和亮度权重。

另一个参考是 [Prague Sky Model](https://github.com/PetrVevoda/pragueskymodel)，对应 Wilkie 等 2021 年的辐亮度/衰减拟合模型与后续光谱扩展。官方完整数据约 2.2 GB，还覆盖能见度、反照率和偏振；地面版约 103 MB。其公布的高度/太阳范围也不同，不能直接用文件体积估计我们“固定介质、任意太空海拔”的压缩率。可以借鉴拟合表示和衰减建模，当前未移植其实现，也没有同设备实时性能结论。

后续值得优先解决的是高空薄光照区的入射积分，以及局部插值尾部。若重启全辐亮度压缩研究，应先隔离前向峰和大气顶边界，再比较真实查询成本；不要继续单纯提高全球球谐阶数。
