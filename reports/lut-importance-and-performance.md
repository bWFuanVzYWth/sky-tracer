# 混合大气 LUT：重要性求积、重复计算与常量优化

> 历史阶段记录：当前默认配置已由[性能预算与简化审计](lut-performance-budget.md)替代，常驻 7.91 MiB、启动约 0.39 秒。下文的 13 MiB 配置、可选首阶缓存及其接口均属于当时实验；首阶缓存已从当前实现移除。

2026-09-19。接续 [映射拟合与精度审计](lut-fitted-mapping-quality.md)。所有改变已接入 `sky-hybrid-atmosphere` 的 `Config::balanced()`，demo 的 `hybrid-4d` 自动采用。冻结参考与 PT 没有重烘焙。

**最终仍为 48×176×24×12 的四波长源项、256² SkyView；常驻 13.001 MiB，启动峰值载荷 1013.7 MiB，RTX 4090 启动求解约 1.6 秒。** 相比映射阶段约 2.55–2.67 秒，耗时减少约 36–39%。这些是实测单次启动范围，不是跨设备性能保证，也不含设备／管线创建；最终 evaluate 的管线创建约 28 ms。驱动和输出目标内存另计。

图集：`out/hybrid_perf_v1/visual/index.html`。完整结果：`out/hybrid_perf_v1/summary.json`。每组输出保存配置、阶段计时；最终结果还保存映射校准和 shader checksum。

## 1. 重复计算：已实施

|改变|处理方式|取舍|
|---|---|---|
|四种气溶胶重复计算相位表坐标|每个正／负反射方向各算一次 cube-root 坐标、索引和权重，共享给四物种|主要加速项；物理相位表不变|
|源项卷积重复查高度剖面|CPU 在源项高度节点预存 5 组散射系数及其和，共 6 个 vec4/高度|增加 4.5 KiB 常驻；不缓存整条光线|
|固定太阳状态几何|每个高度／太阳状态预存太阳径向分量|避免每个角积分方向重复 sqrt|
|首轮读取全零多重散射源项|首轮跳过间接体源查表|地面直接照明和单次散射照常计算|
|高空源项重算角基|Rayleigh 二次型基只算一次，在四个高度／太阳角点间共用|高空分支也避免低空相位／绕轴坐标计算|

以下隔离重要性采样变化，保持旧积分权重与同一组分辨率。时间为单次测量，不能把所有差值精确相加：

|阶段／配置|启动秒|峰值载荷 MiB|
|---|---:|---:|
|前期去重后，尚未共享相位坐标|2.422|1013.7|
|共享相位坐标后，不启用常量特化和首阶缓存|1.948|1013.7|
|再启用常量特化|1.873|1013.7|
|再启用首阶缓存|1.801|1508.7|
|最终重要性分配，首阶缓存关闭，采用|1.631–1.638|1013.7|
|最终重要性分配，首阶缓存打开|1.550|1508.7|

数学等价的去重／特化／缓存改变单独比较，43 个场景的最大场景 P95 差异 **0.000304%**，最大场景 P99 **0.00142%**，最极端单像素 **0.0166%**。运算次序改变会产生 f32 舍入差异，不宣称逐 bit 相同。

`cache_single=true` 可在首轮保留每条入射光线的直接单散射辐亮度，以后只积分间接体源和更新的地面照明；缓存求解后释放。最终只省约 **80 ms／5%**，却增加 **495 MiB** 临时显存，默认关闭。把所有路径采样或卷积权重都缓存会产生很大的存储与带宽负担，这轮不采用。

另外尝试过 CPU 预计算运行时相机／太阳三角函数；CPU 与 GPU 的 f32 运算差异在近太阳场景造成约 0.13% 的 P95 改变，收益不值得这项扰动，已恢复 GPU 原几何计算。

## 2. 常量优化：已实施

在创建 WGPU pipeline 时通过 override 固定映射标志、相位混合权重、绕轴多项式参数及是否缓存单散射。编译器可以删除固定映射的备用分支。相位与绕轴常数来自同一份嵌入 JSON，CPU／GPU 不维护两套校准值。

单独测量从 1.948 秒到 1.873 秒，约 **4%**；较早代码上的收益仅约 1%。因此这是较小、受编译器与计时波动影响的收益，最大收益仍是相位索引去重。保留 `specialize_constants=false` 诊断入口。物理介质、反照率变化仍触发重新求解，相机和太阳变化不会重算固定介质多重散射。

## 3. 重要性采样：值得在哪里做

这里采用确定性非均匀求积，没有增加蒙特卡洛噪声。原算法已有太阳中心图表、地平线两侧图表，以及沿路径的高度非均匀步进。本轮评估的是如何分配这些节点的权重。

### 高空入射角积分：采用重新分配

35 km 以上本介质没有气溶胶，出射卷积是平滑的 Rayleigh 二次型。继续给太阳方向大量积分权重，对地平线亮带和地球阴影的采样不划算。保留太阳集中图表于低空，在 **12–35 km** 平滑衰减它的权重，35 km 以上完全交给地平线两侧图表。

实现上，太阳图表采用 `sw`，地平线图表采用 `1-sw`，始终保持分区权重和为一。**这没有删除太阳照明，也没有删除高空单次散射**：相同物理入射场仍由剩余图表完整积分。权重为零的光线不再执行输运；高空状态约三分之一的原图表光线可跳过。

对照共用同一个 64×64 角积分诊断解，源项网格、路径步数和迭代阶数完全相同：

|测试|旧权重 P95|新权重 P95|
|---|---:|---:|
|400 km 地影，三组近边界太阳高度中的最坏值|2.618%|0.538%|
|43 场景中最坏值|2.618%|0.575%（108 km 地影）|
|额外 48 个独立高空视图，最坏值|0.576%|0.587%|

独立视图覆盖 48、72、119、121、180、280、700、1400 km，太阳相对几何地平线 −0.55°、+0.13°、+0.65°，方位 60°／135°，16° 视场；不用于先前映射拟合。它们说明改善**不是逐场景单调的**：最坏 P95 略升，但该场景最大像素差从 1.058% 降到 0.898%。选择新权重基于总体收敛、显著困难场景和运行成本，而非保证每个分位数都更好。

诊断解也不是物理真值。48×48 与 64×64 新权重结果的最大场景 P95 差仍为 **0.334%**；64×64 新旧权重之间最大 **0.328%**，在新增独立视图中为 **0.075%**。这些独立分区对照帮助避免只对某一种加密布局“过拟合”。不能把当前约 0.58% 当作总物理误差上界。

### 沿路径采样：已有收益，保留现值

当前步进在高度上使用对数分配，尺度 0.25 km。固定步数下改为沿路径均匀，或把尺度换成 0.1／1 km，没有一致优势。以下与同一份旧加密输运解比较，作为参数敏感性，不能当成单独路径积分真值误差：

|场景 P95|0.25 km，保留|均匀路径|0.1 km|1 km|
|---|---:|---:|---:|---:|
|太阳高度 5° 近景|0.067%|1.036%|0.071%|0.076%|
|太阳高度 0° 近景|0.436%|0.832%|0.419%|0.958%|
|蓝调太阳侧|0.451%|0.945%|0.593%|0.459%|
|太阳高度 −8°|0.607%|0.771%|0.727%|0.402%|

均匀路径试验也没有测得速度优势。太阳集中宽度和地平线幂次已分别试验，不存在比当前低空宽度 0.01、幂次 3 更稳的全面替代。继续沿这些全局标量搜索的优先级较低。

### 哪些后续方向仍值得做

最终八轮求解的 GPU 阶段累计：入射输运约 **938 ms**，源项卷积约 **621 ms**，矩积分约 **41 ms**，地面更新约 **7 ms**。前两项占绝大部分成本；优化小表收益有限。

若继续投入，应先在入射输运中显式对齐太阳可见性／阴影边界，尝试按高度与太阳状态分配节点，而不是统一增加角采样。现有加密结果说明还有约 0.3–0.6% 量级的局部收敛空间，但**尚未实现这种自适应边界求积，不能给出其加速倍数**。每个出射方向再各自进行相位重要性追踪，会破坏当前对入射光场的复用，需先解决成本问题；本轮不采用。

## 剩余精度瓶颈与实际限制

最终 43 场景中 SkyView 对同源项直接积分的最大场景 P95 为 **0.474%**。另外 222 个高度／太阳扫描视图的最大场景 P95 **0.868%**，最大场景 P99 **1.934%**，单像素最大 **5.835%**。近太阳、掠射和薄大气弧仍有少量尾部像素，不能宣称插值伪影彻底消失。

原映射审计中，8→12 迭代的最大场景 P95 改变约 0.383%，主要在蓝调暗部；将 4D 表整体加密的最大变化约 0.434%，光学厚度大幅加密只改变约 0.026%。这些是之前积分布局的消融数据；新权重后没有重做每一项，作为剩余优先级的证据，不作为最新严格误差分解。

相对冻结全光谱参考的最终 P95：

|场景|总差异|
|---|---:|
|中午太阳周围／中午地平线|0.600%／0.925%|
|日落|2.132%|
|蓝调太阳侧／反太阳侧|2.255%／1.344%|
|飞机黄昏／30 km 移动地影|4.328%／3.815%|
|108 km 上缘／400 km 核心黄昏|29.824%／15.710%|

这包含四波长近似、太阳盘近似、两端输运离散与参考插值。高空约 **16–30%** 的差异依然存在，本轮没有将它解决，也没有证据把它全部归于四波长或任一求解器。接下来精度工作应单独核对两条输运链，而非继续盲目增加表大小。

## Demo 与验证

RTX 4090 Vulkan、512×384 输出、4 次预热／32 次测量；GPU 时间包含呈现，不含启动与参考读取：

|更新|GPU 中位时间|
|---|---:|
|仅相机变化|0.0133 ms|
|太阳高度变化，重生成 SkyView|0.3133 ms|
|复用缓存|0.00512 ms|

太阳变化的 CPU 编码＋提交＋等待中位约 0.524 ms，不是纯 CPU 计算时间。太阳方位变化和相机变化只投影已有 SkyView；观察高度或太阳高度变化才更新它。

验证包括 Rust 映射端点／单调／逆映射测试、远太空 f32 稳定性、Naga WGSL 验证、demo release 编译与实际 GPU snapshot、43 核心视图、222 扫描视图、48 新高空视图。结果读取检查有限值。缓存失效规则、介质与反照率改变实际源项、真空 `L=0,T=1` 均通过；六条四波长有限线段组合的最大相对辐亮度差为 **0.00274%**，透射率绝对差 **5.25e−6**。

质量结论仅覆盖当前固定大气和灰色地面反照率 0.18。更换物理参数能正常重算，但需要重新检查拟合与重要性分配；校准不构成全介质保证。

## 复现

工作区已有冻结参考、拟合配置和查询文件。在根目录运行：

```powershell
cargo test -p sky-hybrid-atmosphere --lib
cargo build --release -p sky-hybrid-atmosphere --example evaluate
cargo run --release -p sky-hybrid-atmosphere --example evaluate -- --out out/hybrid_perf_v1/final --queries out/four_wave_sun_v1/queries.json --config crates/sky-hybrid-atmosphere/configs/balanced.json
cargo run --release -p sky-hybrid-atmosphere --example evaluate -- --out out/hybrid_perf_v1/sweeps --queries out/hybrid_mapping_v3/sweeps.json --config crates/sky-hybrid-atmosphere/configs/balanced.json
python scripts/run_hybrid_perf_v1.py
python scripts/run_hybrid_importance_holdout.py
cargo run --release -p sky-hybrid-atmosphere --example validate -- --out out/hybrid_perf_v1/invariants.json
python scripts/summarize_hybrid_perf_v1.py
```

脚本跳过已有完整结果；清空实验输出或使用新目录时，早期 `plain`／`both` 与后期 `*_v2` 会运行同一份最新着色器，因此不能复现历史代码的耗时差。旧 shader 保存在 `out/hybrid_mapping_v3/perf_baseline`，历史单次计时作为记录保留。当前不同采样与缓存开关的消融可以独立复现；汇总也需要映射阶段的对照数据。
