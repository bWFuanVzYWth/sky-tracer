# 接近正午的朝日地平线缺陷

2026-09-14。此检查针对用户反馈的“接近中午时，太阳正下方地平线仍有缺陷”。此前圆环修正保留，但原先诊断剔除了 `ray.z <= 0.01`，没有覆盖这次的位置。

## 原因与修正

v3 太阳轴围绕当前高度的几何地平线进行带符号平方映射。65 个节点中，最后两层太阳高度约为 70° 和 90°。太阳接近天顶时，固定散射角的球锥退化，粗糙的太阳轴插值会把同一条地平线视线投影到差别很大的物理方向。既影响首阶查询，也影响逐阶传递。

v4 使用 `sun_aligned_angular`，资源映射标记为 `rho-solar-horizon-square-zenith-cap-cone-split75-angle-mixture-v3`：保留旧表索引 0–62 的太阳节点及区间映射，在其上方附加向天顶加密的角度段，总计 97 个太阳节点。地面太阳节点由 512 增至 1024，避免附加区间稀释原有低太阳角采样。其余辐亮度轴、散射角映射、射线步数、角积分和 16 阶截断保持原配置。

映射使用固定的归一化区间比例，后续增加分辨率会同时细分低太阳角和天顶区间。例如 193 节点会在整个 97 节点表中插入中点；不会把额外节点永远只分配给天顶而让其它区间停止收敛。

曾尝试将 65 个节点重新分配到地平线与天顶，但蓝调首阶测试出现约 26% 的偏差，因此弃用。最终方案保留旧低太阳角节点，两个资源在这些首阶节点上的相对 L2 差约 `3.15e-6`，是 f32 映射舍入量级。

观察高度 200 m、550 nm、朝日方位，直接积分采用 4096 个射线区间与 64 个太阳盘样本。积分不查询辐亮度 LUT，但复用高分辨率消光表；因此它隔离了首阶辐亮度映射及射线离散误差，不是全部输运误差的严格上界。

## Rec.2020 资源与复现

输运仍使用全部 41 个输入波段和 f32/wgpu，完成后再将辐亮度节点转换为线性 Rec.2020。RGB 资源保存三个 f32 辐亮度通道、三个已乘太阳光谱的透射后辐照度通道；直接太阳盘使用后者。另保留约 21.5 MB 的原始光谱光学厚度，供后续有限线段研究，运行时显示不上传它。

RGB 输出没有应用曝光、色调映射、量化或 BC6H。太阳轴的对数插值与光谱积分不交换，因此 RGB 的非节点查询还需单独对照源光谱结果；不能仅凭节点转换宣称所有查询无损。出现负 Rec.2020 通道时使用有符号线性插值。

完整输出已校验：**633,350,504 bytes**，其中三个通道文件各 203,948,040 bytes，光谱光学厚度 21,495,808 bytes，manifest 10,576 bytes。光谱源中间资源约 8.36 GB，已完成全部 41 波段、16 阶；RGB 资源可独立用于当前 demo。

在上述六个实际 GPU 视窗中，排除太阳周围 1° 后，RGB 导出相对同一 v4 光谱查询的最大天空相对 L2 为 **0.00123%**，最大单像素 RGB 范数相对差 **0.00428%**，均出现在朝日蓝调场景。每像素指标的分母下限为该区域最大 RGB 范数的 `1e-6`，这不是任意时间和高度的误差上界。统计见 `out/noon_rgb_export_metrics.json`。

```powershell
cargo run --release -p sky-atmosphere-lut -- bake --out out/lut_reference_v4
cargo run --release -p sky-atmosphere-lut -- export-rgb out/lut_reference_v4 --out out/lut_reference_v4_rgb
cargo run --release -p sky-atmosphere-lut -- inspect out/lut_reference_v4_rgb --verify
cargo run --release -p sky-realtime-demo -- --experiment offline-lut --asset out/pt_noon_085/asset.json
```

CPU 诊断：`examples/horizon_check.rs`、`scripts/plot_noon_horizon.py`。实际 demo 画面对照计划：`scripts/noon_comparison_cases.json`。旧资源仍按旧映射读取，不能修改 manifest 冒充新烘焙。

验证：LUT 与 demo 的 29 项测试通过，覆盖旧圆环、天顶加密、地面/天空隔离、真实 GPU 首阶与查询、太阳盘、RGB 转换及文件损坏检测；LUT crate 的严格 Clippy 通过。demo 的严格 Clippy 仍有两项原有 `too_many_arguments` 提示，位于共用显示参数接口。所有新 GPU 工作均在检查 MicroHH/mircohh 未运行后启动。

这次修正针对接近天顶太阳的地平线插值；v3 报告中 400 km 朝日大气边缘的全域精度问题没有因此自动解决。有限距离雾及动态遮挡体积光仍需各自的误差验证。
