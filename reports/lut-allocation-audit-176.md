# 176 个太阳节点与辅助 LUT 分配审计

2026-09-19。混合 crate 的 `Config::balanced()` 和 `configs/balanced.json` 已由 177 改为 **176**，demo 沿用该配置。其余运行时映射保持原状；本文的其他分配是已测候选，不是已经启用的生产参数。

结果：`out/hybrid_allocation_v2/summary.json`。CPU 试验使用 f32 物理场计算，没有重烘焙大型参考资源。另进行了 176/177 两次小型混合 GPU 求解、43 场景对照及既有缓存/有限线段验证。

## 176 节点的影响

节点数 176 对应 **175 个插值区间**，仍使用 `u*(N-1)`；没有为了对齐删掉物理端点，也没有将坐标除法误换成位运算。

|表|176 太阳节点的物理纹理尺寸|格式|有效载荷|
|---|---|---|---:|
|低空 MS 源|4224×192，即 176×24 太阳/相位、24×8 海拔/锥角|RGBA16F|6,488,064 B / 6.1875 MiB|
|对数平均入射亮度|176×48|RGBA32F|135,168 B / 132 KiB|
|高空 Rayleigh 矩|1232×25，即每太阳状态 7 个 texel|RGBA32F|492,800 B / 481.25 KiB|
|地面边界辐亮度|176×1|RGBA32F|2,816 B / 2.75 KiB|
|太阳光学深度|1024 方向×256 海拔|RGBA16F|2 MiB|
|SkyView|256×256，低天空 96 / 高天空 96 / 地面 64 行|RGBA32F，存 log RGB|1 MiB|
|气溶胶相位输入|1024 角节点×4 组分×4 波长|f32 缓冲|64 KiB|

加上其他几何、方向、光谱和状态辅助数据，常驻估算 **10,513,056 B / 10.026 MiB**，比 177 版本少 41,216 B。启动峰值载荷为 1,056,668,320 B，仍约 1 GiB；此峰值不是这些常驻表的大小。

低空源、平均亮度和高空矩的有效行字节数现在都是 256 B 的整数倍，纹理回读不再需要相应的行尾 padding。正常纹理读取受驱动平铺布局影响，不能仅凭逻辑尺寸对齐承诺显著加速。RTX 4090 这次同程序相邻测量：176 节点求解 2.374 s，177 节点 2.383 s；一次对照不足以认定可靠的性能增益。

43 场景中，176 相对 177 的直接积分图像差异大多较小，最大 P95 出现在太阳 −8° 的暗蓝调场景，为 **1.330%**；其次是 −4° 的 0.306%，轨道地影约 0.24–0.25%。−8° 相对既有更密版本的 P95 从 0.835% 变为 1.736%。这不是纹理越界，而是所有太阳节点的位置变化影响了多次插值和迭代。更密版本也有采样偏差，不能将它称为无偏真值。保留用户要求的 176，后续应通过改善太阳映射恢复这一敏感区域的精度。

已按 176 节点重新拟合此前的简单候选。新上下文上的单轴源项 P95：海拔 1.084%→0.438%，太阳 0.208%→0.091%，相位 0.625%→0.568%，锥角 1.380%→0.766%。这些仍是参考派生 SH 源的轴向实验，不是新映射实际参与 GPU 迭代后的天空误差。

## SkyView：最值得先改分配

使用冻结完整 RGB 参考作为连续查询教师，生成相同大小的 SkyView，再与直接查询对比。排除可见太阳盘，包含太阳附近散射。这里测的是缓存插值误差，不混入四波长/平行太阳/新求解器误差。

当前方位映射为 `cos(azimuth)=1-2*u²`，第一个方位间距约 0.45°。太阳不接近天顶时，这不足以保存前向光晕。候选为：

`cos(azimuth)=1-2*u⁴`

正向查询 `u=sqrt(sqrt((1-cos(azimuth))/2))`，只比当前多一次平方根；无额外纹理查询、无反解循环。

|场景|当前分配 P95|只改方位为四次方 P95|另改行数 64/128/64 P95|
|---|---:|---:|---:|
|太阳 47° 近景|1.680%|0.252%|0.152%|
|太阳 5° 近景|3.054%|0.189%|0.128%|
|太阳 0° 近景|1.657%|0.071%|0.067%|
|正午地平线|0.204%|0.204%|0.117%|
|108 km 大气边缘|0.722%|0.720%|1.349%|

**方位加密有明确收益，垂直行数不能全海拔一刀切。** 将下天空 96 行减至 64 行，在低空能腾出预算给上天空，但会损害高空边缘和部分地影。保留地面 64 行也有必要：改成 32 行时，夕阳、蓝调和飞行高度场景普遍变差。512×128 虽然总 texel 数不变，垂直精度损失明显，不推荐。

从太空看，当前 96 个“上天空”行直接填黑，却仍占 37.5% 的纹理。候选将其复用给大气壳，成为 192/0/64 行，配合方位加密，400 km 轨道暮光 P95 从 1.791% 降至 0.649%。部分其他轨道地影视角有小幅回退，因此应按观察高度/边界几何设计行分配，并做连续海拔扫描，避免切换布局造成时序跳动。

还发现独立的计算重复：`build_sky` 中每个 texel 都进行 24 次仰角反解，而同一行的结果完全相同。适合在观察者/太阳变化时预计算 256 个行角，约 1 KiB，再供构建 pass 使用；大气外边缘分支还会重复反解最后两行，也可复用这些常量。这个小辅助表用于减少计算，不是增加复杂解码。收益需要实际 GPU 计时，本文未改 shader。

## 透射率：角度有余量，分层和切线附近仍欠采样

33,410 条分层/随机偏移高度与方向探针，四波长，CPU f32 8192 步光学深度作为参照；4096→8192 的透射率相对误差 P95 为 0.0019%，最大约 0.0102%。表节点用与当前算法相同的 1024 步生成，再模拟 f16 存储和双线性光学深度插值。

统计相对误差只计透射率大于 1e-4 的通道，另外保留所有通道的绝对误差：

|分配|容量|透射率 P95|最大相对误差|最大绝对误差|
|---|---:|---:|---:|---:|
|当前 256 高度×1024 方向|2 MiB|0.0706%|7.665%|0.002914|
|256×512，原映射|1 MiB|0.0817%|7.496%|0.002920|
|128×512，原映射|0.5 MiB|0.1036%|12.153%|0.003078|
|256×512，分层高度锚点＋单侧三次角映射|1 MiB|0.0652%|3.778%|0.001089|

最大误差集中在介质分层附近的掠射路径，特别是约 2 km 高度；减半方向节点几乎不改变原方案的最坏误差。只增加方向分辨率不会有效解决这个问题。

候选高度坐标在 `sqrt(h)` 上作短分段线性变换，固定 0、1、2、11、12、35、120 km 锚点及节点索引 0、24、56、112、128、176、255；反解只用于构建。正向可以写成一次 sqrt 加固定 hinge 乘加，代替当前 log/sqrt 混合。角度由双端集中改为 `mu=mu_h+(1-mu_h)*u³`，查询只需一次立方根，减少在天顶的重复密集采样。

这说明存在“容量减半、总体与尾部误差同时改善”的候选，但 **3.78% 的局部透射率误差仍未消除**。角度与高度耦合使分层切线路径跨越多个单元，不能仅用平均 P95 判断可交付。建议先在 256 高度上验证分层/切线映射，之后再决定把方向降至 512；暂不将此候选设为默认，也不建议扩容。

## 地面光照与平均亮度：应按自身插值方式评价

地面表只有 2.75 KiB，不值得为容量压缩增加热路径计算。它目前与 4D 求解共享太阳状态，因此增加独立地面节点还意味着安排新的方向积分，不能只扩大纹理就获得新信息。

对冻结参考的 1024 点地面辐照度重采样：176 点、现有映射与线性插值的 P95 约 **1.370%**；改用新拟合太阳映射、仍然线性插值，降为 **0.316%**。把现有映射直接加至 256 点只有 0.665%，所以应优先改善分配。对数插值还能进一步下降，但会增加指数运算；不作为本轮首选。

地面统计使用自身峰值 1e-6 的相对分母下限，并只计模长大于此下限十分之一的点。教师含有限太阳，当前混合求解使用平行太阳；原型落地时要额外检查太阳过几何地平线时的直接照明边界，不能把这里的数字当成地面亮度真值误差。

平均亮度表已经使用 log 插值，其 132 KiB 大小合理。独立测量平均亮度时，新太阳映射 P95 为 **0.201%→0.089%**；将 MS 源的拟合高度节点直接套给它则是 **0.281%→0.337%**。后者说明优化最终源 `shape*exp(mean)`，与单独优化平均亮度不是同一目标。建议继续共享高度/太阳状态以保持源重建一致，按最终源和路径积分误差联合决定节点，而不是为这张小表单独降低分辨率或引入另一套查找。

## 高空矩与相位表

高空 Rayleigh 矩的高度/太阳网格应该继续覆盖太空入口需要的状态。每状态当前存 7 个 RGBA32F texel，不是 7 个 SH 阶数；方向内容来自 Rayleigh 卷积的二阶矩和离散积分归一化。无需再为它增加方向维度或压成会损失地影的低分辨率天空图。

可以研究只做代数重排，将每状态 7 texel 降至 5：用 `x²=1-y²-z²`，把分子预合并为四个四波长系数，分母预合并为四个标量。数学表达能力不变，约省 137.5 KiB，并减少高空查询的读取次数；f32 重排误差需另测。它的收益优先体现为查询成本，容量不是主要矛盾。

气溶胶相位表总计仅 64 KiB。对现有输入表做均匀 cubic-cosine 重采样，1024→512 的单组分局部最大相对误差可到 **4.77%**，1024→256 可到 **12.25%**。这些不是最终天空误差，但对太阳附近尤其不值得冒险。保留 1024 节点与现有 cubic-cosine 坐标；不要将 MS 源的 24 点方向分配混用于相位函数输入。

## 优先顺序与检查

1. SkyView 方位角加密、消除同一行的重复反解；保留地面行预算。
2. 改进太阳坐标，联合检查 MS 源、平均亮度、地面边界和 −8° 蓝调，而非增加太阳节点。
3. 透射率采用分层/切线友好的低成本映射，验证尾部后再决定方向维度减半。
4. 高空矩的 7→5 代数打包。相位输入表保持不变。

目前只有太阳维度 176 已启用。Naga shader 验证与 demo 编译通过；176 配置已通过实际 GPU 缓存失效/重用、介质变化、真空及六组有限线段组合检查。其他候选的图像数字来自 CPU 冻结参考重采样，不代表新 GPU 框架的最终精度或帧耗时。
