# 严格 16 MB LUT 预算的 CPU 实验（2026-09-18）

**可以做出 16 MB 内的天空 LUT，当前 CPU 原型的近地主体误差约为百分之一量级；还不能把它当成全海拔参考质量的成品。** 本轮选出的表示计入索引、太阳表和坐标/元数据预留为 **15,994,444 字节**，小于十进制 16,000,000 字节。没有启动 GPU、烘焙或 PT，也没有替换 demo 的 470 MB 默认资源。

这是已计算的原型结果，不是对 16 MB 所能达到的理论极限的判断。仍使用冻结的 v6 光谱解作为参照，其本身的已知偏差没有算入这里的压缩误差。

## 这个体积下实际达到了什么程度

沿用 82,856 个非网格查询，其中 67,387 个光谱教师 RGB 长度 > 1e-8 的查询参与相对误差统计。包含中午、夕阳、蓝调、地平线密集方向、太阳周围、30/120/400 km 和最高约 22,025 km 的随机海拔。统计的是线性 Rec.2020 向量相对误差，不是 ΔE，也不代表同等比例的可见色差。

|场景|P95|P99|说明|
|---|---:|---:|---|
|近地中午，太阳 85°|0.40%|0.69%|太阳附近另列，避免被全景统计掩盖|
|近地太阳 47°|0.42%|0.63%| |
|近地夕阳，太阳 0°|1.10%|2.07%| |
|近地蓝调，太阳 −6°|0.62%|1.19%| |
|12 km 暮光|0.68%|1.08%| |
|30 km 地影|5.66%|13.81%|个别有意义亮度的方向约 61%|
|120 km 大气边缘|5.57%|19.84%|最大值主要来自极暗方向|
|400 km 轨道|4.13%|12.40%|局部约 43%，尚不能忽略|
|全部查询|**2.71%**|**6.73%**|中位数 0.264%，1.81% 的有效查询超过 5%|

额外按用户关心的方向检查：

- 中午太阳外 **0.27°–2°**：这组 20 个查询的 P99 **4.01%**，最大 4.02%；因此“中午全景 P99 <1%”不能解读为太阳周围也 <1%。这里是散射光晕，未包含直接太阳圆盘。
- 中午离太阳 **10°–30°**：485 个查询，P99 **0.406%**、最大 **0.471%**。
- 中午几何地平线 ±3°：4,096 个查询，P99 **0.692%**、最大 **0.796%**。
- 蓝调几何地平线 ±3°：4,096 个查询，P99 **1.57%**、最大 **2.47%**。
- 轨道几何地平线 ±3°：有效查询 P99 **16.12%**，最大 **43.20%**。

整体最大值约 111%，出现在接近大气顶、辐亮度只有约 1e-8 的方向；不过不能把所有高空误差都解释成黑场百分比放大，30 km 地影和轨道边缘也存在可见亮度下的大误差。没有做 GPU 显示、时间连续性视频或完整视觉验收，因此不宣称没有条带或圆环。

## 最合适的已测表示

选中的网格为 **24 高度 × 32 观察位置 × 97 太阳位置 × 65 相位位置**，共 **4,842,240 个 RGB 节点**。原参考是 `80×32×193×257`。

观察方向轴保留原来的 32 点，地面/天空两侧独立。高度取原高度轴的子集，保留约 0.2、1、2、11、12、35 km 等层次；太阳和相位节点也是原节点的子集。没有重新计算输运。本轮少量需要改变观察轴分辨率的对照只作线性重采样；原参考该轴采用线性插值，因此此步骤与光谱积分交换。

存储继续使用 f32 指数、符号和块内整数差值，但尾数降到 **6 位**。每 16 个节点共享三个整数基值和位宽，相同块复用。计算和插值均为 f32。解码先还原每个角点，再执行原来的 log/PCHIP 插值。

|组成|字节|
|---|---:|
|块索引|1,210,560|
|辐亮度编码|14,062,988|
|太阳衰减表|589,824|
|坐标、参数、元数据及对齐预留|131,072|
|合计|**15,994,444**|

资源已打包到 `out/lut_16mb_resource/`：`lut.bin` 包含按 256 字节对齐的三个数据段，`resource.json` 给出偏移、SHA-256、坐标和解码参数。实际文件包 **15,869,229 字节**；上表另为运行时坐标缓存等预留空间。这里讨论的是 LUT 数据预算，不含帧缓冲、参考图片或 GPU 驱动开销。该包是 CPU 原型格式，目前不能直接传给 demo 的 `--lut`。

`out/lut_16mb_candidate/decoded_*.f32` 是 CPU 验证中间文件，不属于发布包或 GPU 载荷。所有 14,526,720 个通道节点已核对实际块解码结果与预期量化编码一致。打包沿用已验证的整数编解码器，但本轮新格式尚未做 GPU 接入验证。

## 为什么当前应该继续优化分配，而非降低精度

相同 `24×32×97×65` 网格保留 f32、完全不量化时，整体 P95/P99 已经是 **2.706% / 6.755%**；最终 16 MB 版本是 **2.707% / 6.735%**。尾部百分位的轻微下降是误差偶然抵消，不是量化改善了物理精度。主要问题是少了网格点，继续增加尾数位数不能解决高空地影。

对照也显示，直接把观察方向从 32 减到 16，很容易让高空掠射误差大幅增加。相同约 15.5 MB 的普通缩放 f16 网格，若使用 `36×16×65×65`，整体 P99 约 **49.35%**；使用 `24×32×49×65` 则约 **15.97%**。预算在各维度的分配比“统一降一点分辨率”更重要。

下一步应在这个预算内优先试：近太阳相位节点重分配、顶层/轨道入射边界单独细分、地影临界位置的局部修正或自适应节点。可以继续由现有参考烘焙器在 CPU 上合成数据。应保留一组新的验证查询，避免只针对本轮场景调参；还要补时间及海拔连续扫查。

## 同预算方案对照

本轮实际生成并独立 CPU 解码比较了不同块编码、六组网格分配、五组局部 PCA，以及 BC6H 的线性、平方根、对数输入。

|代表方案|预算 MB|整体 P95|整体 P99|
|---|---:|---:|---:|
|选中的稀疏网格＋6 位尾数块编码|**15.994**|**2.71%**|**6.73%**|
|较小网格＋缩放 f16，`24×32×49×65`|15.548|5.53%|15.97%|
|较密网格＋BC6H，`32×32×97×129`|15.918|7.32%|13.29%|
|分区 log PCA，20 阶、i8 系数|14.755|13.95%|43.16%|

BC6H 在这里有足够的体积优势，但块内误差抵消了更密网格的收益；平方根和对数预变换没有在本轮实验中整体胜过线性版本。该结论仅覆盖所测网格排列、归一化和 Intel basic 编码器设置，不代表 BC6H 或专用编码器不存在更好的结果。

局部 PCA 保留全部参考节点的位置，体积也合格，但会把误差扩散到较暗的方向。简单增加分区数量也没有解决高空问题。本轮测试的是沿相位/RGB 的局部 PCA，不是完整张量分解或 Prague 模型的复现，不能据此否定其他低秩结构。

## 太阳表、视距雾和运行时的边界

原 RGB 太阳表约 18.9 MB，本身已超预算。原型只保留可见太阳实际查询的天空分支，在原光学厚度坐标内重采样为 `96×1024×RGB`，按未衰减太阳颜色归一化后存 f16，总计 589,824 字节。地面遮挡由几何判断负责，太空真空方向直接用未衰减太阳颜色。

对原天空分支的全网格回采样，归一化太阳向量长度 >1e-4 时，相对误差 P95/P99 为 **0.132% / 1.115%**，最大约 21.5%；全网格归一化绝对向量误差最大约 0.00404。上方天空误差表不包含直接太阳圆盘，太阳表需单独验收，尤其是接近消失的低亮度太阳。

**有限距离视距雾/体积光尚未包含在这个格式和质量验收中。** 当前太阳颜色衰减表不是通用的有限线段透射表示，不能直接拿它代替所需的透射率。固定大气参数有利于另外压缩这部分数据，但还要给它留预算，并检查光谱到 RGB 近似以及近距离差分误差。当前的 16 MB 结果应理解为天空/地面边界辐亮度加直接太阳所需数据。

所有实验为 CPU 操作。没有测新格式的 GPU 帧率；保留原插值方式也意味着不能直接用硬件线性过滤替代全部角点查询。demo 的现有 470 MB 资源、格式和默认配置保持不变。

## 复现与证据

CPU 拟合：`scripts/probe_lut_16mb.py`、`scripts/probe_lut_coarse16.py`。编解码及非网格查询：`probe_lut_16mb_bits`、`probe_lut_16mb_bc6h`、`validate_lut_16mb_cpu` 三个 Rust examples。绘图和特殊方向统计：`scripts/summarize_lut_16mb.py`。LUT crate 全目标严格 Clippy 通过；原始 RGB 数据校验和已重新验证。

```powershell
# 使用新输出目录；不创建 GPU 设备。
python scripts/probe_lut_coarse16.py out/lut_reference_v6_rgb out/new_grid --shape 24 32 97 65 --bc-source
cargo run --release -p sky-atmosphere-lut --example probe_lut_16mb_bits -- out/new_grid out/new_16mb 6
cargo run --release -p sky-atmosphere-lut --example validate_lut_16mb_cpu -- out/lut_reference_v6_rgb out/new_16mb
```

- `out/lut_16mb_candidate/candidate.json`、`validation.json`：选中表示、预算及分场景误差。
- `out/lut_16mb_resource/resource.json`、`lut.bin`：仅包含运行时数据的原型发布包。
- `out/lut_16mb_summary.json`：各方案和特殊方向统计。
- `out/lut_16mb_quality.png`：分场景误差与误差累积分布。
- `out/lut_v6_packed_cpu.queries.json`、`colors.json`：冻结的查询及逐光谱插值教师值。
