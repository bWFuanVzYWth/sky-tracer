# 四波长 + 各向异性多重散射：精度原型与生产设计

2026-09-18。已实现四波长资源合成、wgpu 积分器及 demo 入口。波长为 **450、510、580、650 nm**，固定大气和地面反照率。完整持久载荷 **13,302,768 B = 12.687 MiB**，小于 16 MB（无论按十进制还是 MiB）。CPU 合成耗时约 **43.4 秒**，没有重新烘焙冻结 v6 参考。

本文记录逐像素 SH **精度原型**及其基准数据。demo 现已默认切换为固定 MS 方向纹理 + SkyView；当前更新依赖、内存和实测性能见 [缓存实现报告](lut-four-wave-cache.md)。本文的约 50 ms 耗时属于保留的诊断积分器，aerial-perspective 缓存仍未接入。

## 采用的输运分解

沿视线实时求解四波长的一次太阳散射和消光，多重散射查询当前位置的方向源项：

```
J_ms(x, v, λ) = Σ_k σ_s,k(x, λ) ∫ p_k(v·ω, λ) L_reference(x, ω, λ) dω
L(a,b) = ∫_a^b T(a,x) [J_sun(x,v) + J_ms(x,v)] dx
```

参考入射场包含天空与地面反射，排除太阳盘；因此卷积生成二次及更高阶散射，不会重复加入直接太阳。实际打到地面时另加经过视线衰减的地面边界亮度，使用冻结参考的总地面辐照度。最后才用已搜索的四波长权重和原完整光谱白平衡转为线性 Rec.2020。

这里没有把 `L_reference − 实时单次散射` 直接当作多重散射表。后者会把参考亮度插值误差混进残差，也不能直接成为任意有限线段的局部散射源。当前办法相当于对冻结入射场应用一次输运算子；它不是重新迭代收敛的参考解，更不是无偏解。

保留原始四种气溶胶（含 sulfate）、实测相位表和 50 个介质剖面节点，没有沿用旧 8 波长 demo 的简化密度或缺失物种。计算使用 f32；f16 只用于保存归一化方向系数与太阳光学厚度。

## 方向表示与预算

以径向向上为 z、朝向太阳的水平切向为 x，投影到实球谐。球对称介质与固定均匀地面使入射场关于该平面镜像对称，只需余弦项；这不等于把场假定成各向同性。

相位卷积在球谐上按阶乘以实际相位的 Legendre 矩。瑞利相位仅有 `a₀=1, a₂=0.1`；气溶胶系数从原实测表、沿三次余弦坐标积分得到。每个步进位置仍使用当地真实物种散射系数。

|维度/载荷|当前分配|
|---|---|
|高度|完整保留参考的 80 个节点，含介质分层位置|
|太阳角|每个高度保留 193 点，沿用参考的当地地平线、暮光、反向地平线和天顶混合 CDF|
|0–35 km 入射方向|16 阶余弦球谐，153 系数|
|35 km 以上入射方向|2 阶，6 系数；当前固定介质此处已无气溶胶|
|方向系数|9,819,840 B，四波长 f16，逐高度/太阳状态归一化|
|均值、坐标、剖面、相位、地面辐照度等|337,200 B，f32|
|太阳光学厚度|3,145,728 B，384×1024×RGBA16；只存不被地面遮挡的一支|
|持久 GPU 载荷合计|**13,302,768 B / 12.687 MiB**|

归一化均值单独保留 f32，避免暮光和极高空的小信号在 f16 中下溢。均值做 log 插值，带符号的归一化方向系数线性插值。35 km 节点仍保留 16 阶，防止 35 km 以下在高度插值时过早丢掉气溶胶方向信息；当地气溶胶变为零后仅需 2 阶。

预算不包括输出帧缓冲、PT 对照图和后续按帧更新的缓存。当前精度原型输出两张屏幕尺寸 RGBA32F：Rec.2020 亮度（或调试用四波长亮度）与四波长透射率。生产缓存也需要另列预算，不能通过忽略它们宣称整个渲染器只占 12.69 MiB。

## 精度证据

先测方向压缩，再测实际 GPU 完整积分。局部源项检查包括 9 个高度/太阳状态、每个状态 37 个方向、4 个波长，共 1,332 项；包含太阳附近、地平线两侧、夕阳、蓝调、30 km 地影和 108/120 km。

|局部方向表示|源项相对误差 P95|P99|
|---|---:|---:|
|各向同性，0 阶|64.90%|103.32%|
|8 阶|4.47%|7.60%|
|16 阶|1.37%|3.29%|
|24 阶|0.776%|2.49%|
|32 阶|0.412%|1.89%|
|实际打包表，含量化与高度/太阳插值|**1.378%**|**3.271%**|

实际打包源项最大误差约 8.19%，所以不能宣称所有方向都已达到 1%。投影和角积分的独立分辨率从 64×128 提高到 128×256 时，角积分参考的差异 P95=0.166%、最大 0.625%。以上均为局部源项误差，不是最终天空误差。

实际 GPU 使用高度导向的 128 步积分、16 个有限太阳采样，在之前独立的九张 192×96 视图上重新计算。下表是相对冻结 **41 波段** 参考的线性 Rec.2020 向量误差；有效像素要求参考范数 >1e-8，分母下限 1e-7。太阳盘不参与该组数值比较。

|场景|128 步完整结果 P95|128 → 512 步差异 P95|
|---|---:|---:|
|中午光晕|0.466%|0.029%|
|中午地平线|0.783%|0.017%|
|夕阳|1.959%|0.033%|
|蓝调朝阳方向|2.779%|0.231%|
|蓝调背阳方向|1.751%|0.008%|
|12 km 暮光|4.085%|0.156%|
|30 km 移动地影|3.686%|0.048%|
|108 km 上层大气|29.828%|0.003%|
|400 km 轨道暮光|15.912%|0.041%|

这是新积分器全部误差与参考偏差的合计，不能拿前轮“保留理想多重散射、只替换一次散射波长”的指标替代它。轨道有效像素 P95 也不能和把大量黑色背景算入分母的 8.57% 混用。

128 步是本原型的默认值。64 步在 12 km 暮光相对 512 步的 P95 差异约 1.37%；直接缩减到 64 步暂不作为默认。继续增加到 512 步并不能消除高空与冻结亮度 LUT 的差异。

### 高空大差异的归因

另外用未压缩的参考入射场，做 256 步、64×128 双方向角积分的 CPU 固定点检查。四个中心方向上，GPU 512 步相对这次直接角积分重建的 Rec.2020 差异为：

|中心方向|GPU 与直接角积分重建|
|---|---:|
|108 km、太阳 0°、方位 90°、俯仰 −0.5°|0.0114%|
|400 km、太阳 −6°、当地地平线上 3°|0.0089%|
|12 km、太阳 −7°、当地地平线上 4°|0.0126%|
|0.2 km、太阳 −6°、俯仰 5°|0.3102%|

108 km 中心处，冻结亮度 LUT 相对该重建值高约 **27.1%–27.3%**（四个波长）。压缩源项并没有产生这个量级的差异。四个中心检查不是整张图的误差上界，也不能凭此证明新结果就是物理解；但足以避免错误地把参考亮度插值偏差重新拟合进源项。此轮保持参考冻结。

## 雾、太空与一致性

`Renderer::segment_km` 支持从相机到有限距离；太空的真空段被裁去，进入 120 km 大气顶之后使用相同的局部源项。因此不需要另烘焙 400 km、2000 km 等外部观察高度。

增加了 GPU 四波长线段合成检查：白天、蓝调、108 km 和地面边界四种情形，验证 `L_ac = L_ab + T_ab * L_bc` 与 `T_ac = T_ab * T_bc`。512 步下最大亮度差异约 **0.000297%**，最大透射率绝对差约 **2.45e-6**；真空为 `L=0,T=1`。

这是空气中传输接口和合成一致性的验证，尚未接入有场景深度的 froxel 雾效。四个波长的透射率不能无条件变成一组对任意 RGB 材质都严格正确的 RGB 乘数；后续需要明确表面颜色的光谱近似或验证 RGB 消光近似。当前烘焙场对应晴空太阳照明；动态遮挡可先影响实时一次散射项，固定多重散射背景不会自动包含新的遮挡或云层反馈。

## GPU 性能与下一阶段结构

RTX 4090 / Vulkan，512×384、128 步、中午光晕视角，GPU timestamp，4 帧预热 + 8 帧统计，包含 demo 显示 pass：

|工作负载|GPU 中位耗时|
|---|---:|
|相机变化、重新逐像素积分|49.69 ms|
|太阳变化、重新积分|49.59 ms|
|相机/太阳/高度不变、复用上次输出|0.0051 ms|

去掉方向系数内层重复的地址计算后，输出逐位一致，但耗时仅从约 50.4 ms 降到约 49.7 ms，收益很小，不能将其称为主要性能突破。瓶颈是每个步进点重复解码最多 153 个方向系数。

生产版沿用旧 demo 的更新结构，按以下顺序推进，保留当前逐像素模式作为 GPU 精度对照：

1. **SkyView 只随太阳相对高度、观察海拔更新**，相机旋转只重投影。太阳方位通过旋转查询处理；固定介质不必重算资源。
2. **把一次散射与多重散射的缓存分开**。一次散射在太阳附近有强相位峰，优先缓存各物种的去相位路径积分、在显示像素处恢复实际相位，避免小 SkyView 网格重新产生光晕圈；有限太阳与遮挡耦合要单独对照当前积分器。
3. **多重散射解码进入较低分辨率的方向缓存**，仅缓存已经沿视线积分的结果，避免最终屏幕逐像素、逐步展开 153 项。先用现有九场景及连续太阳/海拔扫描检查插值，不能凭平滑外观直接减少地影分辨率。
4. **aerial-perspective/froxel** 复用相同四波长局部源项，缓存有限线段的 L 和 T，再与场景深度合成。为天空调好的二维边界亮度缓存不代替这个局部源项。

剩余约 2.70 MB（按十进制 16 MB）或 3.31 MiB（按 16 MiB）的静态资源预算先留给真正有收益的方向阶数或缓存。如果缓存也算进同一 16 MB 总额，需要明确从这部分扣除。当前不继续缩减高度/太阳角密度，也不再次搜索波长。

## 运行与复现

```
cargo run --release -p sky-realtime-demo -- --experiment four-wave --asset out/pt_noon_085/asset.json
```

`--experiment four-wave` 默认加载 `out/four_wave_source_v1`，也可用 `--lut` 指定。原 `unreal-8wave`、`offline-lut` 入口保留；新入口支持同样的 PT、绝对差、带符号差及 HDR 显示。

```
cargo run --release -p sky-atmosphere-lut --example export_four_wave_cpu -- out/lut_reference_v6 --candidate out/wavelength_counts_v1/N4_best.json --out out/four_wave_source_new
cargo run --release -p sky-atmosphere-lut --example validate_four_wave_gpu -- out/four_wave_source_v1 --queries out/wavelength_search_dataset_v1/queries.json --out out/four_wave_validation_v1 --steps 32,64,128,256,512
python scripts/summarize_four_wave.py
cargo run --release -p sky-atmosphere-lut --example validate_four_wave_segments
```

关键产物：

- `out/four_wave_source_v1/resource.json`：布局、颜色转换、参考校验和与载荷校验和。
- `out/four_wave_validation_v1/visual/index.html`：九场景实际积分对比。
- `out/four_wave_validation_v1/summary.json`：完整画面与步数收敛指标。
- `out/four_wave_validation_v1/source_cpu.json`：局部压缩源项检查。
- `out/four_wave_fixed_point`：直接角积分固定点检查原始数据。
- `out/four_wave_validation_v1/segments.json`：有限线段一致性。
- `out/four_wave_validation_v1/performance_offsets.json`：最终 GPU 计时。

已通过球谐正交/瑞利卷积测试、WGSL Naga 校验、Rust 编译、实际 wgpu 图像输出与有限线段 GPU 检查。静态九视图和四条线段不是连续运动验收；尤其不能据此承诺所有太阳角、海拔与方向都没有伪影。
