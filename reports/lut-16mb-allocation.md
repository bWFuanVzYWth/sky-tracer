# 16 MB LUT 的当前分配与理论优化方向

2026-09-18。全部新增诊断为 CPU 查询；未修改生产坐标、demo、参考烘焙器或 16 MB 资源。这里的“最优”指在给定查询权重、误差标准、解码成本和冻结参考解下的存储分配，不能脱离这些条件给出唯一的四个整数。

## 当前到底存了什么

物理输入是高度、太阳高度、观察方向的两个角。球对称大气允许把太阳方位移入相对观察方位；“时间”不是独立的日历时间轴。存储采用变换后的四个轴：

|轴|参考节点|16 MB 节点|当前分配|
|---|---:|---:|---|
|高度 h|80|24|保留原节点子集；原高度 CDF 中插值|
|等相位锥上的观察位置 v|32|32|8 点触地、24 点天空；地平线两侧分别映射|
|太阳高度 s|193|97|原 CDF 每隔一个节点取样；CDF 随高度改变|
|相位角 θ，即视线与太阳夹角|257|65|原分区 CDF 每隔三个节点取样；随高度、太阳角和触地分支改变|

共 4,842,240 个 RGB 节点。辐亮度编码 14,062,988 B，块索引 1,210,560 B，太阳表 589,824 B，坐标等预留 131,072 B，共 15,994,444 B。并不是把 16 MB 按四个轴相加分摊；稠密网格的成本近似与四轴点数的乘积成正比，实际编码还受重复块和位宽影响。

24 个高度节点（km，显示值取近似）：

```
0, .00164, .01792, .05193, .19419, .41929, 1, 2,
3.48784, 5.35418, 11, 12, 16.54895, 21.73120, 27.22512, 35,
44.88213, 55.16952, 65.67268, 76.33626, 87.12319, 98.00773,
108.97127, 120
```

选点先保留首尾和接近 0.2、1、2、11、12、35 km 的节点，再按原节点索引的最大间隔补点。它不是对 RGB 场插值误差求最优的结果。5.35–11 km 间隔 5.65 km，27.23–35 km 间隔 7.77 km，约 45 km 以上间隔约 10–11 km。高度 CDF 为 35% 的对数平方根项加 65% 的线性高度项。

太阳轴的 CDF 是经验混合：25% 均匀角度、20% 局部地平线附近、20% 暮光区、15% 镜像地平线附近、20% 太阳近天顶。混合权重不是每段最终点数。在 0.2 km 处，97 点中有 51 点位于太阳高度 −20°～10°，21 点位于 70°～90°；47° 附近相邻太阳节点间隔约 5.69°，85° 附近约 1.22°。120 km 处重新随当地地平线分配。

观察轴不是均匀天顶角。对每个太阳角和相位角形成的球锥，先分触地/天空，再对离几何地平线的余弦距离 δ 使用 δ/(δ+sqrt(16/r)) 映射。这样把点集中在掠射变化区。当前 32 点就是参考的全部节点；“不能再减半”仅是当前映射下的实验结论，不是所有参数化的数学下界。

相位轴固定划分为 32、24、8 个区间（总计 64 个区间、65 个节点），边界是等相位锥开始/结束穿过几何地平线的精确位置。每区又使用 65% 对数角度、35% 均匀角度的 CDF，叠加向分区边界聚集的映射。这些边界用于避免旧版圆环，应该保留其几何意义。

但是固定区间比例在压缩后明显失衡：0.2 km、太阳 85°、天空分支的相位前几个节点为 **0°、0.683855°、1.558214°、2.657707°**，而 85.4544°～95.4544° 的地平线交叉区占 **24 个区间**。尾部 8 个区间此时退化为同一点。太阳 0° 时却有 33 个节点集中在 0°～约 0.455°。因此当前映射不能给近太阳区域提供近似恒定的精度。

上述 0.2 km、85° 等角度分布由对应状态的坐标映射计算，用于解释采样密度；这些状态本身未必恰好是存储的高度/太阳角节点。真实查询还会使用相邻高度、太阳角的坐标图及插值。

退化节点的块压缩已经复用了部分数据，所以不能把“8 个退化区间”直接换算成等比例可回收字节。删除退化区间、重新分配有效节点后仍应实际编码计量。

太空不需要把高度轴继续延长：真空段不改变辐亮度，射线先解析推进到 120 km 大气顶，旋转到入口处的当地角度，再查表。因此所有太空观察者共享大气顶的三维角度边界表。新增大气内部高度层不能改善这个边界切片的角度误差。

## CPU 实验把误差定位到哪个轴

本轮保留相同 82,856 个查询，取消量化，分别恢复高度、太阳、相位到参考分辨率，并检查全部八种组合。下表是相对冻结光谱教师的线性 RGB 向量误差 P99，辐亮度长度门槛仍为 1e-8。**这些恢复分辨率的诊断不受 16 MB 限制，不是新的发布资源。**

|改变|中午太阳外 0.27°–2°|30 km 地影|120 km 大气边缘|400 km 轨道|全部|
|---|---:|---:|---:|---:|---:|
|24×32×97×65，未量化|3.92%|13.64%|19.60%|12.43%|6.76%|
|仅高度恢复到 80|3.85%|4.13%|19.60%|12.43%|4.54%|
|仅太阳恢复到 193|3.94%|13.01%|19.67%|11.69%|6.50%|
|仅相位恢复到 257|**0.08%**|10.66%|**0.21%**|4.40%|5.06%|
|高度和相位同时恢复|0.03%|**0.71%**|0.21%|4.40%|2.92%|
|太阳和相位同时恢复|0.09%|10.48%|0.02%|**0.013%**|4.85%|

结论是条件性的：

- 中午近太阳和大气顶以相位轴为主要瓶颈。
- 30 km 地影高度轴的收益最大，但相位误差也参与；两者同时恢复才从 13.64% 降至 0.71%。
- 轨道先修相位，之后太阳轴的误差才充分显现。仅恢复太阳看起来收益小，不能因此全局砍掉太阳节点。
- 在稀疏基线上把观察轴 32→16，整体 P99 从 6.76% 升到 **53.33%**，轨道 P99 达 282%。当前映射下，它不是首先应削减的轴。
- 全部轴恢复时，本例程对原 RGB 缓存查询 **逐值完全一致**。对光谱教师仍有整体 P99 0.01045% 的差异，来自原 RGB 节点积分与光谱查询的非线性插值顺序等已有差异。

以上不是按轴可加的误差贡献百分比。不同轴相互作用，P99 不具有可加性，而且较高分辨率偶尔会移除误差抵消。中午近太阳单独区域只有 20 个查询；后续分配拟合必须增加独立密集角扫，不能把这个小样本的百分位当严格上界。

## 理论上应优化什么

### 先指定误差目标

如果只按均匀球面平均平方误差，太阳附近和窄地影会被小面积稀释；若只看无限制的相对误差，接近全黑的尾部又会占主导。适合当前目标的是分场景约束，加亮度下限的相对误差、绝对误差和局部连续性检查。

可用的拟合损失为

```
D = Σ_scene w_scene E_scene[ ||L_hat-L_ref||² / (||L_ref||²+L_floor_scene²) ]
```

另对近太阳、日落、蓝调、地平线、轨道设置各自的 P99/最大绝对误差验收，时间/高度/角度扫查检查接缝和斜率突变。这里的权重与曝光下限要显式记录。没有应用场景分布或可见误差标准，不能声称某个整数分配是唯一最优。

### 沿一个轴：看曲率和实际插值残差

下面是局部光滑、线性插值的简化推导，不是现有四维非线性插值的严格全局误差界。设所插值标量为 f，节点间距为 Δ，局部二阶导数幅值为 K，则

```
|e| <= max|f''| Δ² / 8
```

若控制局部最大误差，使 K Δ² 大致相等，所以节点密度 n=1/Δ 应满足 **n ∝ sqrt(K)**。若最小化加权积分平方误差，D≈∫w K² n^-4 dx，并固定 ∫n dx=N，变分得到 **n ∝ (w K²)^(1/5)**。这两个目标给出不同的最优密度。

这说明不是“亮的地方多放点”，也不是简单按一阶梯度分配：一个斜率很大的线性函数仍可由两个节点精确表示。对正辐亮度的 log 插值，应研究 log(L) 的弯曲程度；例如指数衰减在 log 域可能很平滑。近零或有符号 RGB 要用有下限的向量误差，不能盲取各通道对数。

现有相位是限幅单调三次插值，且坐标图随其他轴变化，不能直接宣称处处有四阶收敛。实际应以冻结教师的中点/多点重构残差估计收益，再用上述密度规律作初始化。各向异性网格理论也强调误差范数及方向导数结构会改变最优网格，而不是给所有轴相同点数。[Cao, SIAM J. Numer. Anal. 2007](https://doi.org/10.1137/060667992)

### 在轴之间：均衡每字节的边际收益

先忽略坐标耦合和误差相关性，设各轴的均方误差近似 D_i=A_i N_i^(-2p_i)，有效近似阶数为 p_i。固定每节点字节数时，B≈b∏N_i，约束等价于固定 Σlog N_i。拉格朗日条件为

```
2 p_i D_i = 常数
```

相同阶数下应使各轴误差项大致均衡，而不是节点数均衡。线性插值模型 p=2 时，N_i 比例随 A_i^(1/4) 变化。

真实编码中 b 不恒定，恢复实验又不是无穷小变化，不能把上表 P99 直接代入公式。可执行的离散版本是：每次候选细分/重分配后，比较 **验证损失下降量 / 实际增加的字节数**，按收益排序。索引、额外节点坐标、块对齐、残差、以及随机访问成本都要计入；也应把量化位数作为候选操作与加节点竞争。

### 坐标对齐通常比全局增点更有效

地影和地平线是随高度、太阳角、观察角共同移动的窄变化区。全局张量网格会把为某一局部现象添加的节点复制到所有其他组合，成本相乘。更合适的是保留几何边界对齐，按区域改变节点密度；必要时使用少量规则分块和局部残差表。

例如地影的主控制量可用太阳相对当地地平线的高度、沿观察路径的太阳射线切线高度/最近遮挡距离近似表达。它们能给映射提供物理初值，但天空辐亮度是整条路径积分，单一局部阴影坐标不能保证消除全部耦合。最终仍要由场数据的重构误差验证。

Bruneton 的公开实现也采用几何路径长度改善地平线采样，并对有限线段利用边界量之间的关系；这些是坐标设计的依据，不是当前 16 MB 分配的最优性证明。[官方实现及推导](https://ebruneton.github.io/precomputed_atmospheric_scattering/atmosphere/functions.glsl.html)

## 针对当前数据的分配建议

1. **先重新分配相位轴的 65 个节点。** 保留地平线拓扑边界，但取消所有状态固定 32/24/8 的配额。根据每段的重构残差决定前向核、宽角度区和交叉边界的密度；保留有限太阳盘尺度及前向峰的采样。在中午把部分交叉区和退化区的逻辑槽位让给 0°～2°，但跨太阳高度要保证连续，不能直接硬切表。
2. **把大气顶当独立三维边界优化。** 太空查询只需这一层的角度数据，所以给顶层额外相位/太阳分辨率比对所有高度统一加密便宜。它仍须与内部高度极限连续，不能另贴一张不一致的轨道天空图。其真实压缩字节尚需测量。
3. **24 个高度节点重新按误差选择。** 当前 27.23–35 km 的宽间隔首先值得细分；5.35–11 km 也应检查。近地多个节点是否能释放必须看误差，不能因物理间距小就认定浪费；保留大气密度分段附近的必要节点。若全局 24 层无法兼顾，可只在暮光/掠射分区增加高度分辨率。
4. **观察轴暂保留 8+24；太阳轴做条件优化。** 前者减半已经证实代价大。后者总体 97 点未必都必要，但顶层在修复相位后仍需要更好的太阳采样，不能仅凭当前全局 P99 对太阳轴减半。
5. **保持量化误差小于主要插值误差。** 当前 6 位尾数后的尾部误差几乎等于同网格 f32，所以先移动节点/改坐标。后续若个别区域插值已很准确，应在那里增加位数或改变通道编码，不必全局统一加位。

这套方向有测量与局部理论支持；尚未求得在 16 MB、实时解码成本及全场景误差约束下的数值最优解。本轮不指定一个未经验证的新四元组冒充最优。

## 视距雾对“最优”的额外要求

当前 15.994 MB 包用于天空/到边界辐亮度和直射太阳，并未包含有限距离雾的完整表示。若最终 16 MB 必须同时覆盖它们，需提前给线段传输数据留预算。

单波长上可用 L_segment = L_p − T_pq L_q，但短线段相减会放大端点误差；压缩只优化天空的相对误差并不够。另有 C(T_lambda L_lambda) 通常不等于 T_RGB * C(L_lambda)：光谱投影不与逐通道乘法交换。应另外验证 RGB 透射近似、少量光谱矩/基底或直接拟合线段量的方案，不能把现有太阳颜色衰减表直接当通用透射率。动态遮挡体积光也需要额外的可见性处理。
