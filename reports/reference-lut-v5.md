# v5 参考 LUT：重新分配坐标与 CPU 数据合成

2026-09-14。目标是固定当前大气、气溶胶、相位和地面反照率，烘焙任意太阳高度、观察高度和观察方向的确定性参考场。光谱只用于输运和颜色积分；生产资源可以只有线性 Rec.2020。PT 保留为独立验证，不作为生产拟合数据来源。

本轮先解决 v4 坐标误差，再扩大必要的轴。完整 41 波段已在 `out/lut_reference_v5c` 完成。**后续 [CPU 全域验收](reference-lut-v5-quality.md) 发现高空掠日与暮光残差，暂未通过全域合成基准验收。** 本文保留设计阶段的 550 nm 试烘焙证据；不能据此宣称全域达到同样精度。用户要求继续仅使用 CPU，未启动新的 GPU 检查。

## 分配方案

| 维度 / 积分 | v4 | 新 reference |
|---|---:|---:|
| 高度 | 64，rho 映射 | 80，近地对数与高空均匀分量混合 |
| 球锥内观察位置 | 32，天空 / 地面 75% / 25% | 32，保留光程加密与天空 / 地面分支 |
| 太阳高度 | 97，地平线平方 + 天顶补丁 | 193，连续密度混合，含两个地平线特征 |
| 散射角 | 256，全局固定节点 | 257，128 / 96 / 32 个区间跟随球锥与地平线的交点 |
| 相位轴插值 | 线性 | 单调三次 Hermite，四点模板 |
| 光学厚度表 | 128 × 1024 | 384 × 4096 |
| 射线 / 消光积分步数 | 256 / 2048 | 256 / 2048 |
| 入射方向积分 | 两套 16 × 32 | 两套 16 × 32 |
| 有限太阳盘积分 | 4 × 16 | 4 × 16 |
| 散射 / 地面交互阶数 | 16 | 16 |

4D 索引顺序是高度、球锥内观察位置、太阳高度、散射角。257 节点有 256 个区间，恰好允许在 1/2、7/8 处对齐分区。验证拒绝不满足 `8k+1` 的该类配置。旧资源仍按旧映射读取；新映射标识为 `height-mixture-solar-two-horizons-topology-cubic-phase-v5`。

### 高度与太阳高度

令 `x=h/H`，高度 CDF 为

```
0.35 log(1 + sqrt(x)/a) / log(1 + 1/a) + 0.65 x
a = sqrt(0.01/H)                   // km
```

这样保留亚米级近地层，同时避免 rho 在高空留下过大间距。逆映射在 `sqrt(h)` 中求解，所有输运和查询仍用 f32。太空视线先裁剪到大气入口，真空不占用高度轴；400 km 等外部视点的入口几何仍需专门验证。

太阳高度分配五个连续密度分量：25% 全角均匀、20% 几何地平线附近、20% 地平线下 6° 的暮光区、15% 反向地平线附近、20% 天顶附近。各 CDF 都归一化到 [-90°, 90°]，整体单调、可逆，没有旧方案在某个固定高度角切换两张表的接缝。

反向地平线项不是为了地面太阳盘：高空 / 太空的背日大气边缘，沿射线移动后局部太阳高度会落在 `-horizon` 附近。去掉此项的试验即使改善地面，也会让轨道视点大幅退化，因此最终保留。

### 相位轴与地平线对齐

设太阳天顶角 `alpha=acos(mu_s)`，地平线天顶角 `beta=acos(mu_h)`。太阳球锥与地平线相切的散射角为

```
theta_lo = abs(beta-alpha)
theta_hi = min(alpha+beta, 2*pi-alpha-beta, pi)
```

它们决定前部、跨地平线、后部三个区间。区间边界始终落在相同节点索引上，内部通过实际散射角的对数 / 均匀混合 CDF 和端点加密映射分配节点。这样，太阳移动时不再让球锥的拓扑变化穿过任意一个固定散射角单元。

插值在这套对齐后的坐标中保留球锥位置。跨高度时保留视线到地平线的归一化距离，同时保持天顶 / 天底端点和相对方位角。把 v4 的每角落物理视线投影直接套到新分区，会重新引入偏差，已在纯空气质量函数和首阶试验中排除。

相位轴使用 PCHIP 式调和平均斜率；相邻区间共享导数，局部极值处斜率为零，输出限制在中央两节点范围内。此处的平滑性指相位坐标中的相邻单元，不能推导整个 4D 场对所有物理变量都 C1。太阳轴仍在正辐亮度的对数域插值，高度和球锥位置线性插值。相位已经存在辐亮度中，不进行相位后乘。

## 已完成的精度诊断

首阶表为实际 GPU 烘焙结果，与原有 4096 步确定性积分点对照。积分基线复用旧光学厚度表，因而这个数字包含旧 / 新消光表差异，不是完整输运的严格误差上界。统计均为 550 nm，按选定查询点计算相对 L2。

| 查询组 | 点数 | v4 | v5 |
|---|---:|---:|---:|
| 地面高度，跨太阳高度与方向 | 357 | 1.675% | 0.284% |
| 其中正午低地平线 | 135 | 1.394% | 0.074% |
| 其中暮光 | 105 | 4.857% | 0.413% |
| 太阳附近 | 48 | 0.676% | 0.386% |
| 跨高度 | 297 | 9.239% | 1.068% |
| 400 km 轨道视点 | 72 | 34.174% | 0.380% |

16 阶总场另外测了 30,020 个连续方向。观察者 200 m、太阳正下方、地平线上 1–10°、0.01° 步长，比较相邻 `100*d(log L)/d(degree)` 的最大跳变：

| 太阳高度 | v4 | v5 |
|---|---:|---:|
| 60° | 1.227 | 0.074 |
| 80° | 3.629 | 0.092 |
| 85° | 3.648 | 0.066 |

这是梯度跳变指标，不是辐亮度百分比误差。新的总场明显减少了周期性台阶，仍有缓慢起伏，不能仅凭导数变平滑认定物理解已收敛。

![最终三次插值试烘焙的总辐亮度与导数](../out/lut_reference_design/noon_gradients_v4_v5.png)

其它检查：

- 169 条透射路径，与 8192 步直接消光积分对照。在直接光学厚度小于 10 的 114 条路径中，最大相对透射误差从 4.342% 降到 0.950%。暗路径的相对误差需要结合绝对亮度解释。
- 实际太阳盘平均后的相位函数，在 440 / 550 / 680 nm 的最大插值误差分别为 0.141% / 0.115% / 0.100%。说明没有为地平线精度牺牲前向峰。
- 固定 v5 总场，仅提高源项入射方向积分：当前 16×32 双规则相对 128×256 双规则，所选暮光点差约 -0.14% 至 +0.10%；太阳附近约 -0.79%，30 km 约 +1.02%，120 km 约 +1.54%。这不是高积分精度重新烘焙后的差值。当前优先修坐标，保留下一轮针对高空源积分的收敛研究。

## 容量与生产数据合成

完整参考光谱二进制约 **21.083 GB**；预算为 22,000,000,000 bytes，含元数据预留。未压缩 RGB 导出预计约 **1.801 GB**：1.543 GB 辐亮度 / 太阳表，以及 257.95 MB 保留的光谱消光表。后者不上传当前 RGB 显示路径。单个辐亮度通道约 507.91 MB，仍在所申请的 512 MiB storage binding 范围内；GPU 另有坐标缓存和帧缓存。

这些是参考分配的成本，不是最终生产资源目标。生产流程是：

1. wgpu / f32 完成光谱输运参考场。
2. CPU 选择生产网格或训练 / 验证点；先查询各波段，再积分为线性 Rec.2020。
3. CPU 做坐标重采样、BC6H 编码或低秩拟合，依据独立验证点选择容量 / 误差折中。
4. GPU 只在验证实时采样实现、画质和运行性能时参与。

新增 `synthesize` 不创建 GPU 设备。几何插值模板每个查询点编译一次，按波段串流文件，使用最多 16 个 CPU 工作线程处理查询；f32 补偿求和累加颜色。无需同时载入 41 个大表。成本主要是文件读取 / 校验、随机查表与插值；高质量压缩也可能耗时，但不需要再次求解散射输运。

```json
[
  {"altitude_km": 0.2, "sun_elevation_deg": 85.0, "view_elevation_deg": 1.0, "relative_azimuth_deg": 0.0},
  {"altitude_km": 0.2, "sun_elevation_deg": -6.0, "view_elevation_deg": 5.0, "relative_azimuth_deg": 180.0},
  {"altitude_km": 400.0, "sun_elevation_deg": 20.0, "view_elevation_deg": -20.0, "relative_azimuth_deg": 180.0}
]
```

```powershell
cargo run --release -p sky-atmosphere-lut -- synthesize out/lut_reference_v5c --queries points.json --out out/production_samples
```

输出 `samples.f32` 为按输入顺序排列的 RGB 三元组，附 `queries.json` 与来源、配置、校验和元数据。拒绝部分光谱源和已提前转 RGB 的源，以免把非线性光谱插值 / 颜色积分不可交换的误差带入生产基准。当前输出包含地面、散射天空，**不包含直接可见太阳盘**。

CPU 合成接口已用现有完整 v4 光谱资源实跑：65,536 个覆盖太阳角、方向、近地至太空的查询，41 波段，包含约 8.36 GB 文件读取 / 校验和输出，耗时 **10.06 秒**。结果 786,432 bytes，全部为有限数。该测试用于确认流程与吞吐量，未做精度判定；v5 文件更大、插值模板不同，不能直接套用这个耗时。运行时 microhh 和当前参考烘焙仍在进行，缓存状态也未固定。

```powershell
cargo run --release -p sky-atmosphere-lut --example synthesis_cpu -- out/lut_reference_v4 --out out/cpu_synthesis_v4_benchmark --samples 65536
```

例程额外写入 `timing.json`。同样的命令可以在完整 v5 就绪后更换源 / 输出目录复测。

低秩分解和 BC6H 尚未在 v5 上拟合，不能把先前 v4 的压缩率直接当成 v5 结果。视距雾 / 体积光还需要消光与有限线段的散射数据；本轮合成接口输出的是到大气或地面边界的辐亮度。短线段不宜只用两次近似天空查询相减作为参考，应研究由此烘焙器导出源项并直接积分线段，以及单独验证误差。
