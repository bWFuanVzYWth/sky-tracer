# 旧 8 波长与当前 4 波长运行成本

后续已完成太阳简化误差验证，并将固定 4 点设为实时默认：见 [太阳模型与稳定框架](lut-four-wave-solar-framework.md)。本文保留定位瓶颈时的 16 点数据。

2026-09-18。用户指出太阳变化时当前约 10 ms 明显慢于旧 demo。实际代码和 GPU 计时确认，主要问题是实时路径沿用了参考级的 16 点有限太阳积分；不是 4 波长或各向异性 MS 必须付出这个量级的成本。

## 同口径 demo 对照

RTX 4090 / Vulkan，`out/pt_noon_085/asset.json`，海拔 0.2 km，太阳高度 85° 起逐帧改变，512×384，包含 experiment 渲染和显示 pass，GPU timestamp，排除初始化、CPU 和回读。

|实现|SkyView|积分步数|太阳变化 GPU 中位时间|
|---|---|---|---:|
|旧 unreal-8wave|256×256|128|0.595 ms|
|当前 four-wave|256×256|128|9.702 ms|

旧版当前配置没有复现 0.1 ms，但确实显著更快。相机变化在此测试分别约 0.010 和 0.015 ms。两边的 SkyView 尺寸和步数相同，不能将约 16 倍差距归因于这两项。

代码差异：

- 旧版每步只使用一个太阳方向，两组四波长各查询一次硬件过滤透射率纹理；当前每步用 16 个太阳圆盘方向，光学厚度保存在打包 buffer 中，手动四邻点解包/插值后再取指数。
- 旧版 MS 为两张 64×64 的各向同性表；当前查询具有方向性的固定源，包含高度查找、非线性角度映射、四次角度纹理查询和均值插值。
- 当前保留分层介质、掠射路径的高度导向步进和更复杂的坐标映射。它们增加成本，但不能仅凭代码估计占比。

## 实际消融计时

新增 `profile_four_wave_cost` 示例，通过独立 shader 变体改变太阳积分，demo 默认路径保持不变。每种设置预热 4 帧、记录 24 帧，每帧改变太阳高度以保证重建 SkyView；只计 SkyView + 屏幕投影，不计显示 pass。所有变体仍为 256×256；每个渲染器 MS 展开一次，初始化不计入统计。

|变体|步数|MS|中午|蓝调|
|---|---:|---|---:|---:|
|完整有限太阳 16 点|128|开|10.385 ms|9.883 ms|
|完整有限太阳 16 点|128|关|8.881 ms|8.707 ms|
|完整有限太阳 16 点|64|开|5.622 ms|5.567 ms|
|完整有限太阳 16 点|32|开|3.056 ms|2.804 ms|
|点太阳 1 点|128|开|0.632 ms|0.603 ms|
|点太阳 1 点|128|关|0.209 ms|0.188 ms|
|点太阳 1 点|64|开|0.329 ms|0.319 ms|
|点太阳 1 点|32|开|0.177 ms|0.171 ms|

仅移除 16 点太阳积分、保留各向异性 MS 和 128 步，中午降低约 16.4 倍、蓝调降低约 16.4 倍。关闭 MS 对原始慢路径帮助较小。不同 shader 的编译、寄存器与占用率会变化，这些差值不是可以直接相加的 GPU 模块耗时，也没有据此报告精确的指令或带宽占比。

## 对实时设计的含义

当前瓶颈不能靠反复强调“839 万积分步”解释，因为旧版同样使用这个步数总量。应优先优化单步太阳源的计算：固定相位的太阳圆盘平均可以预计算；有限太阳透射和地影需要保留耦合误差检查，将完整积分集中于确实敏感的区域。之后才检查 MS 坐标计算、查找和存储布局，以及是否能按光路难度分配步数。

单点诊断改变了有限太阳模型，尤其可能影响太阳附近、夕阳和地影过渡；**本次没有将它切成 demo 默认，也没有将 0.632 ms 宣称为保持现有质量的最终性能**。直接把步数降到 32 也尚未通过精度验收。实测说明已有接近旧版速度的计算基础，质量与速度的兼顾仍需通过专门的实时太阳源实现验证。

复现：

```powershell
cargo run --release -p sky-atmosphere-lut --example profile_four_wave_cost
target/release/sky-realtime-demo.exe --experiment unreal-8wave --asset out/pt_noon_085/asset.json --snapshot out/four_wave_cache_v1/old8_noon.png --snapshot-linear --snapshot-yaw-deg 0 --snapshot-pitch-deg 85 --snapshot-fov-deg 12 --benchmark-frames 16
```

结果：`out/four_wave_cache_v1/cost_ablation.json`、`old8_noon.json`、`noon.json`。本次是性能归因，未重烘焙参考、修改波长或更换 demo 的默认精度。
