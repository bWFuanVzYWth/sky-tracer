# 4D 联合压缩：16 MB CPU 原型

2026-09-18。结论：联合压缩值得作为后续主线。本轮保留原参考 **80×32×193×257** 的全部节点位置，以 Tensor Train 表示内部大气，并直接编码大气顶角度边界，得到 **15,701,476 B** 的 LUT 预算。其误差分布优于之前的稀疏网格，但仍有局部失败、近地精度取舍和较高的解码成本，尚未作为生产资源接入 demo。

本轮没有 GPU 运算、重新烘焙或 PT。拟合、重构及查询均为 f32 CPU 运算；f16 仅用于保存因子。误差参照是冻结 v6 光谱 LUT，不包含该参考解自己的输运偏差。

## 联合表示

过去的局部 PCA 使用每个 `(高度, 观察位置, 太阳角)` 的独立系数，压缩相位/RGB 曲线。这已经共享部分曲线形状，但没有继续压缩系数场中的多维相关性。均匀抽稀 `24×32×97×65` 则主要靠减少节点降低容量。

新表示在原四维网格上定义经过亮度归一化和 log1p 变换的场 F：

```
F(h,s,v,p,c) ≈ M(v,p,c) + Σ_a Σ_b A(h,s,a) B(a,v,b) C(b,p,c)
L(h,s,v,p,c) = P(h,s) × ε × expm1(clamp(F, 0, 20))
```

- h 是高度索引，s 是太阳角索引，v 是等相位锥上的观察位置，p 是相位索引，c 是 Rec.2020 通道。
- 秩为 **a=256、b=192**。A 保留高度/太阳的联合变化；B、C 继续共享观察位置、相位和颜色的变化。
- 这是 `(h,s,v,p×RGB)` 顺序的 TT，第一高度单位核心隐含在 A 中，没有额外截断高度轴。不是单一可分离函数的乘积。
- P 是 `(h,s)` 切片的非负峰值；M 是变换后角度场的均值。
- 较均衡的版本使用 **ε=1e-8**。早期 ε=1e-6 版本平均误差更小，但极暗的上层大气误差明显更大。
- 原始极小负 RGB 在拟合归一化时钳为零，此项处理计入最终对光谱教师的误差。

拟合先对 `(h,s) | (v,p,c)` 做随机化截断 SVD，再把剩余张量沿 `(a,v) | (p,c)` 分解。奇异值传入第二次分解，保证第二次截断按实际剩余能量加权。因子写成 f16 后才重构验证。

原参考的 log/PCHIP 插值是非线性的，因此当前验证会先重构每个节点，再执行原坐标变换及插值；没有把因子插值后相乘假定为等价操作。相位信息仍在烘焙的辐亮度中。

TT 利用若干展开矩阵的低秩性，避免存储完整张量；其秩及误差依赖维度顺序和数据本身。标准 TT-SVD 的误差界是张量范数意义上的，不保证天空暗部相对误差或某一场景 P99。[Oseledets, Tensor-Train Decomposition](https://doi.org/10.1137/090752286)

## 为什么额外保存大气顶

纯联合低秩会在非常暗的太空掠射方向出现颜色串扰。许多普通亮场的微小拟合残差，在这些方向会变成很大的相对误差。

所有从太空进入大气的射线都先推进到 120 km 边界，真空段不改变辐亮度。于是完整大气顶只需要 **32×193×257** 的三维表。这一层采用 f32 指数、6 位尾数、16 节点块差值和重复块共享；恢复出辐亮度后替换 TT 的最后一个高度层。内部接近大气顶的查询也使用这一替换后的端点，遵守原来的高度插值。

这保留了所有太空海拔的入口角度信息，且只对一个高度切片付费。它不会自动修复 120 km 以下其他层的极暗尾部。

|载荷|字节|
|---|---:|
|A：高度、太阳角、rank 256|7,905,280|
|B：rank 256、观察位置、rank 192|3,145,728|
|C：rank 192、相位、RGB|296,064|
|角度均值|98,688|
|高度/太阳峰值|61,760|
|大气顶编码和索引|3,473,060|
|太阳衰减表|589,824|
|坐标、参数及对齐预留|131,072|
|合计|**15,701,476**|

选中包位于 `out/lut_joint16_balanced_resource/`，包含上述载荷和 `resource.json`（各文件 SHA-256、参数和来源）。实际文件包 **15,577,270 B**。预算不含帧缓冲、skyview/体积解码缓存，也不含 CPU 验证用的展开数组。此包还不能直接传给 demo 的 `--lut`。

## 原 82,856 查询的结果

线性 Rec.2020 向量相对误差；只对教师 RGB 长度 >1e-8 的 67,387 个查询统计相对百分位。表内为 P99。

|场景|原 15.994 MB 稀疏网格|15.701 MB 联合＋边界，ε=1e-8|
|---|---:|---:|
|近地中午全景|**0.69%**|2.10%|
|近地太阳 47°|**0.63%**|2.51%|
|夕阳|2.07%|**1.27%**|
|蓝调|**1.19%**|1.53%|
|12 km 暮光|**1.08%**|2.39%|
|30 km 地影|13.81%|**3.81%**|
|120 km 大气边缘|19.84%|**0.46%**|
|400 km 轨道|12.40%|**0.47%**|
|随机时间/方向/海拔|7.21%|**2.46%**|
|全部|6.73%|**2.46%**|

整体 P95 从 2.71% 降到 **1.48%**；中位数从 0.264% 上升到 **0.417%**。超过 10% 误差的有效查询比例从约 0.564% 降到 **0.0178%**。这是一种更均衡的高空/困难区域取舍，不是每个方向都改善。

ε=1e-6 的同体积联合版本曾取得整体 P99 **2.03%**，但是随机海拔 P99 **9.34%**，并有极暗方向约 3290% 的误差；ε=1e-8 版本的这一最大值约 **49.0%**。因此不只按整体 P99 选择前者。

## 新增 18,091 个物理查询

为避免只检查旧场景，另外从冻结的 41 波段参考解逐波段插值并积分到 RGB，生成了以下 CPU 验证集：

- 4,096 个中午光晕方向：0.2 km，太阳 85°，离太阳 0.27°–3°，包含完整方位环。
- 10,395 个移动地影方向：26–36 km，高度与当地太阳/观察地平线相对位置一起变化。
- 3,600 个上层大气/太空方向：90、100、108、112、116、119、119.9、120、120.1、150、400、2000 km，覆盖不同太阳角和掠射/向上方向。

这些点未作为 SVD 拟合数据；但新增测试随后用于选择 ε，所以它们属于开发验证集，不能宣称为最后一次完全盲测。

|新增区域|原网格 P99|联合＋边界 P99|
|---|---:|---:|
|密集太阳光晕|4.16%|**0.58%**|
|移动地影|35.58%|**5.28%**|
|上层大气/太空，RGB 长度 >1e-8|107.36%|**34.39%**|

新增全部有效查询的 P95 从 **13.31% 降到 2.36%**，P99 从 **86.55% 降到 6.73%**。这与旧查询的 P99 不是同一种场景分布，不能直接混用。

|第三组相对误差门槛|原网格 P99|联合＋边界 P99|有效查询数|
|---|---:|---:|---:|
|教师 RGB 长度 >1e-8|107.36%|34.39%|2,774|
|>1e-6|95.96%|3.74%|2,417|

这些门槛用于解释暗部误差，不是视觉可见性的判断。新增集最大相对误差约 **135.4%**，出现在 119 km 的极暗向上方向；移动地影区域仍有最高约 **27.2%** 的局部误差，不能只归咎于接近零的分母。还没有进行连续动画或最终画面验收。

## 同轮尝试了什么

以下同样保持全部参考节点，均为 CPU 实际拟合和解码查询，不是理论大小估算。P99 为原查询集整体相对误差。

|表示|预算 MB|P99|
|---|---:|---:|
|全局两组二维因子，rank 128，log1p|15.164|60.07%|
|全局两组二维因子，rank 128，log|15.164|25.26%|
|4×4 高度/太阳分区，rank 16，log1p|15.254|115.46%|
|4×4 高度/太阳分区，rank 16，log|15.254|31.60%|
|纯 TT，336×192，log1p|15.682|21.37%|
|纯 TT，336×192，log|15.682|15.48%|
|TT＋大气顶，256×192，log1p ε=1e-6|15.701|2.03%|
|TT＋大气顶，256×192，log1p ε=1e-8|**15.701**|**2.46%**|

纯 TT 的近地/30 km 表现比全局两因子好，但全域误差被大气顶拖累。直接把四维表交给一次低秩分解并不能自动解决全部问题。单独的几何边界和合适的暗部加权是此次收益的重要组成。

另外试过给每个 `(h,s,v)` 保存独立峰值，以改善归一化，但为此需要减小 TT 秩；15.889 MB 版本整体 P99 约 3.04%，没有取代当前选择。两次早期未按奇异值加权第二次截断的探索也未采用，不作为 TT-SVD 的有效对照。

## 实时解码仍是待解决问题

该 TT 可以随机访问，但直接求一个 RGB 节点需要约 **256×192** 次核心乘加，再做颜色重建；完整查询还涉及原来的多个插值角点。这明显比 BC6H 硬件解码或短 rank 的两因子乘积更重。

更可行的工程方向是按当前太阳/观察高度预收缩部分核心，或在 skyview、体积缓存更新时解码，再由屏幕像素读取缓存。不过射线坐标图会让角点太阳坐标随观察方向变化，不能未经验证就把所有参数收缩为一张简单角度图。所需缓存大小、更新耗时和精度都未测量；若 16 MB 是所有大气资源总预算，缓存也必须在其中安排。

本轮只证实了联合表示的容量/精度收益，**没有证实当前 rank 的直接逐像素解码满足实时性能**。后续应把秩、维度顺序、分区、局部残差和运行时收缩成本共同优化，而不是只追求文件最小。

同样，有限视距雾/体积光没有纳入当前资源。端点差分会放大局部误差，光谱透射的 RGB 近似也要单独验证，不能从天空结果推出线段输运精度。

## 验证与复现

- 全部原节点仍使用原坐标和原插值，先重构后查询。
- 大气顶编码器核对了全部通道节点的量化整数解码结果。
- 另一个 Rust 实现对 2,048 个节点（6,144 通道）直接收缩 f16 核心，对照 Python/BLAS 展开；以 `max(abs(expanded), peak×1e-6, 1e-30)` 归一化，最大差异 **5.78e-6**。这是 f32 计算次序的检查，不是物理误差或 GPU 测试。
- LUT crate 所有目标严格 Clippy 通过；Python 拟合和 Rust 解码均已执行。
- 拟合时间为几十秒以内的 CPU 原型量级，但本轮未做隔离、重复的性能基准，不据此给运行时 FPS 承诺。

```powershell
# 各输出目录必须尚不存在；没有创建 GPU 设备。
python scripts/probe_lut_tt16.py out/lut_reference_v6_rgb out/new_joint_base --rank 256 --tail-rank 192 --transform-floor 1e-8
python scripts/combine_lut_tt_top.py out/new_joint_base out/lut_joint16_top_m6 out/new_joint
cargo run --release -p sky-atmosphere-lut --example validate_lut_16mb_cpu -- out/lut_reference_v6_rgb out/new_joint
cargo run --release -p sky-atmosphere-lut --example check_tt16_cpu -- out/new_joint_base
```

代码：`scripts/probe_lut_joint16.py`、`scripts/probe_lut_tt16.py`、`scripts/combine_lut_tt_top.py`、`scripts/make_joint_lut_audit_queries.py`、`scripts/summarize_joint_lut16.py`。CPU 查询器位于 `crates/sky-atmosphere-lut/examples/validate_lut_16mb_cpu.rs`。

选中验证目录为 `out/lut_joint16_hybrid_floor8/`，其中 `validation.json` 对应原集、`fresh_validation.json` 对应新增集；`out/lut_joint16_analysis/summary.json` 包含分区域和各亮度门槛结果。仅含发布载荷的原型包为 `out/lut_joint16_balanced_resource/`。`decoded_*.f32` 属于可重新生成的 CPU 中间文件，不计入 LUT 预算。
