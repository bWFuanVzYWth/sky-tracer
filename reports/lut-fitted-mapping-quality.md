# 混合大气 LUT：拟合接入与精度瓶颈

2026-09-19。已接入 `sky-hybrid-atmosphere` 与 demo 的 `hybrid-4d`，不依赖运行时加载参考资源。默认使用四波长、f32 输运、平行太阳光；可见太阳盘单独处理。冻结 v6 参考未重烘焙，PT 未重算。

**本报告记录映射拟合阶段的对照：48 高度 × 176 太阳高度 × 24 散射角 × 12 绕太阳方向，常驻 12.997 MiB（含 SkyView），RTX 4090 启动求解约 2.6 秒。** 拟合后最明显的瓶颈是太空地影的入射角积分，而不是继续全面放大 4D 表。

随后已经完成重要性求积、重复计算和常量优化，保留上述分辨率；最新默认常驻 **13.001 MiB**，启动约 **1.6 秒**。本文的旧积分消融与耗时保留作为历史对照，最新结论见 [重要性与性能报告](lut-importance-and-performance.md)。

图集：`out/hybrid_mapping_v3/visual/index.html`。机器结果与全部消融：`out/hybrid_mapping_v3/summary.json`。默认配置：`crates/sky-hybrid-atmosphere/configs/balanced.json`；嵌入拟合参数：`configs/mapping_fit.json`。

## 已接入的分配

|表／维度|当前分配与处理|运行时成本|
|---|---|---|
|源项高度|48 个拟合节点；保留 1、2、11、12、35 km 分层节点；35 km 两侧共享边界|原有二分查找与线性插值|
|源项太阳高度|176 节点；均匀角度项＋3 个 softsign CDF＋小比例天顶项|两高度层共享 asin；各层预存系数，3 个有理式和 sqrt，无 atan|
|源项散射角|`0.61 θ/π + 0.39 cbrt((1−ν)/2)`|与旧坐标同量级|
|源项绕太阳方向|`c + 0.164285714 c(1−c)(2c−1)`，`c=(1−cosψ)/2`|多项式替代 acos|
|平均入射亮度、地面边界|共享新高度／太阳状态网格；亮度仍存 log，地面边界仍线性|不增加表、不增加地面指数解码|
|高空 Rayleigh|精确二次型，7 个 RGBA32F texel 改存 5 个|每角点少读 2 个 texel；不是截断拟合|
|太阳光学厚度|256×1024 RGBA16F；高度在 sqrt(h) 上分段；角坐标单侧三次映射|一侧 cube root；分段线性高度映射|
|SkyView|256²；大气内 96/96/64 行；太空 192/0/64 行；方位角用四次分配|每图表 3 个有理式，逆映射仅在 CPU 更新缓存时计算|
|物理相位输入|每物种 1024 个原始节点，四波长总计 64 KiB|保留原物理插值定义|

太阳光学厚度的高度锚点为 `[0,1,2,11,12,35,120] km`，对应行号 `[0,41,72,157,167,210,255]`。这是对 f32 物理光学厚度曲率拟合的结果，不是照搬源项高度分布。诊断改变表高时会先取整锚点行号，再生成节点，保证分层边界仍在 texel 中心。

SkyView 分别拟合下半天空、上半天空、地面、太空薄壳。近地掠射光线的到地面距离变化很快，另拟合近地地面图表，并在 1–4 km 间平滑混合参数。所有这些选择、系数归一化和 256 行反解都在 CPU 上随观察者／太阳更新；像素着色阶段不增加搜索或迭代。

对远离图表的太阳，softsign 归一化使用避免相消的等价式。若中心 c 位于 `[lo,hi]` 外：

`CDF(e) = (e−lo)/(hi−lo) × (|hi−c|+w)/(|e−c|+w)`。

直接相减两个接近饱和的 softsign 值，会在 36,000 km 的薄大气弧产生明显 f32 误差。这个问题已经通过新增远太空视图发现并修正，不需要 f64。

物理相位输入不做二次压缩拟合：512 节点版本曾出现约 4.77% 的单分量最大误差，且只能节省 32 KiB。它定义介质本身，和已经拟合的 24 节点 MS 出射散射角轴是两回事。平均亮度／地面边界采用联合源项拟合的共享网格，避免为单张表的微小局部收益增加另一套状态求解。

## 为什么选 12 个绕太阳节点

先固定 8 个节点比较新旧映射，再独立增加这个维度，避免把增加内存的效果误算成拟合收益。

|版本|常驻|烘焙耗时（单次）|飞机高度黄昏，对同积分加密网格的 P95|
|---|---:|---:|---:|
|旧映射，8 节点|9.90 MiB|2.29 s|1.79%|
|新映射，8 节点|9.90 MiB|2.26 s|1.39%|
|新映射，12 节点，采用|13.00 MiB|2.55 s|0.43%|
|新映射，16 节点|16.09 MiB|3.01 s|0.32%|

16 节点加 256×512 光学表可以降至 15.09 MiB，但光学厚度测试的最坏相对透射率误差会从 1.88% 上升到 3.87%。目前保留更稳的 1024 角度光学表和 12 个绕太阳节点。这里的 0.43% 是采样收敛差，不是相对物理真值的总误差。

默认常驻载荷中，低空源项约 9.28 MiB、光学表 2 MiB、SkyView 1 MiB、高空二次型约 0.336 MiB、均值约 0.129 MiB，剩余为物理输入、状态和映射缓存。启动峰值约 1014 MiB，求解后临时入射光场和备用迭代表释放；以上不含屏幕目标和驱动开销。

## 实测质量

评价使用线性 Rec.2020 向量相对误差，分母下限 1e−7，参考向量长度大于 1e−8 的像素参与统计。排除可见太阳盘。P95 为单场景像素分位数，不是全场景平均，也不是感知 ΔE。

### SkyView 独立插值误差

用同一个已求解源项的逐像素积分作对照，排除源项精度、光谱近似的影响。

|场景|旧映射 P95|新映射 P95|
|---|---:|---:|
|中午太阳周围|0.329%|0.093%|
|中午地平线|0.212%|0.063%|
|太阳高度 47° 近景|1.732%|0.452%|
|太阳高度 5° 近景|3.196%|0.243%|
|日落|约 0.256%|约 0.032%|
|108 km 上缘|0.386%|0.474%|
|轨道黄昏|约 0.310%|0.105%|

不是每一个分位数都下降：108 km 上缘 P95 略升，但 P99 从 1.94% 降至 0.82%，最大误差从 2.00% 降至 0.85%。

最初全局地面拟合在离地 2 米的掠射方向出现了单行约 7.84% 的尾部误差，而 P95 仅 0.024%；近地地面专用拟合把这个最大误差降到约 0.48%。仍有少数边界像素，例如飞机黄昏最大约 3.30%、轨道黄昏约 2.89%，不能只用 P95 宣称无伪影。

额外测试了 **222 个未用于拟合的视图**：正午太阳高度扫描、−9° 到 +2° 蓝调扫描、分层高度附近、35 km、120 km 两侧，以及 400、2000、36000 km。新 SkyView 的最大“场景 P95”为 **0.87%**，最大场景 P99 约 **1.94%**，单像素最大约 **5.83%**。这是选定视图覆盖，不是任意轨迹的严格误差上界。

36,000 km 日间薄弧的 P95：旧映射 9.03%，新映射在修正归一化相消后 **0.45%**；夜间相应为 2.92% → **0.84%**。旧映射对照已校正 CPU 行缓存在恰好 120 km 时的严格边界条件；临时对照程序造成的空图表问题不计入拟合收益。

### 光学厚度

33,410 条独立物理路径，含分层边界 ±0.001/0.03 km、掠射角与随机高度；oracle 使用 8192 步 f32 积分。4096→8192 步 oracle 自身最大变化约 0.0102%。只对 T>1e−4 的分量统计相对值。

|256×1024 RGBA16F|P95|P99|最大相对误差|最大绝对误差|
|---|---:|---:|---:|---:|
|旧坐标|0.0706%|0.229%|7.665%|0.002914|
|拟合坐标|0.0604%|0.149%|1.884%|0.000777|

整幅天空把该表加密到 512×2048、4096 积分步后，最大的场景 P95 变化只有 **0.026%**。当前应保留这项分配，不应继续大量给它加预算。

## 当前真正的瓶颈

下表均从最终 12 节点方案出发，只改列出的参数；数字是两个结果的最大场景 P95 **变化幅度**。它们不是真值误差、不能相加，耦合维度之间也不保证单调收敛。

|仅改变这一项|最大 P95 变化|主要位置|结论|
|---|---:|---|---|
|入射积分 40×32 → 48×48|3.695%|400 km 地影|当前首要数值瓶颈|
|仅纬向积分 40 → 64|2.671%|400 km 地影|关键集中在积分方向分布|
|仅方位积分 32 → 48|0.702%|400 km 地影|方位也有影响，但较小|
|散射迭代 8 → 12|0.383%|蓝调反太阳侧、−8°|暗部高阶尾项仍可测；不是主要的大伪影来源|
|太阳状态 176 → 256|0.383%|−8°、轨道地影|小部分剩余太阳高度插值；保持 176|
|绕太阳出射 12 → 16|0.365%|飞机高度黄昏|仍有收益，但已经明显递减|
|散射角 24 → 32|0.286%|飞机高度黄昏、日落近太阳|次要方向分辨率瓶颈|
|运行时步数 128 → 256|0.235%|108 km 地影、蓝调|局部可见，全面翻倍成本不划算|
|源项高度 48 → 72|0.182%|低空地影|拟合后不再是主要维度|
|启动积分步数 96 → 192|0.177%|−8°、轨道地影|优先级低于角度积分|
|光学表双轴加密＋4 倍积分步数|0.026%|飞机黄昏、30 km|收益已经很小|

固定原积分、仅把 4D 网格加到 72×224×32×16，当前方案与之的最大场景 P95 差异为 **0.434%**。这说明继续全维度扩大储存表的收益有限。

加密输运 A 使用 72×224×32×16、48×48 角积分、192 步、12 阶；B 将角积分改为 56×48、256 步、16 阶。它们分别耗时约 26/49 秒，常驻约 35.8 MiB，仅用于诊断。两者在 400 km 地影仍相差 **1.84–1.91%**，其他核心场景小得多。因此不能拿 B 宣称“已经收敛”，也不能把当前与 B 的约 2.4% 地影差异直接解释为完整真实误差。

SkyView 还有局部精度空间：升到 512²，太阳 47° 近景 P95 0.452% → 0.088%，108 km 上缘 0.474% → 0.111%。但新增 3 MiB，生成 texel 数变成 4 倍；当前默认不采用。若继续优化，优先拟合上缘／前向峰的剩余曲率或做少量局部修正，而不是扩完整缓存。

下一步最有价值的方向是让入射积分对齐**太阳可见性／地球阴影边界**，用更好的分区与求积节点代替所有状态统一加采样；然后处理 SkyView 薄弧端点和近太阳剩余尾部。蓝调迭代尾项可考虑带误差判据的停止条件，避免所有场景固定提高阶数。

## 性能与验证

最终 demo，RTX 4090 Vulkan，512×384 输出，32 次采样、4 次预热，GPU 时间包含呈现：相机变化 **0.0133 ms**，太阳变化 **0.3195 ms**，缓存帧 **0.00512 ms**。太阳变化的 CPU 编码＋提交＋等待中位约 **0.516 ms**，不是纯 CPU 计算时间。启动约 2.67 秒；这些不是 4K 或所有介质下的最坏保证。

验证通过：Rust 映射端点／单调／逆映射与远太空 f32 稳定性、Naga 全 WGSL 验证、demo 编译和实际 GPU snapshot、43 场景对照与逐项消融、222 新视图、实际介质／反照率变化触发重算、相机／太阳缓存失效规则、真空 `L=0,T=1`。六条光谱有限线段组合测试最大相对辐亮度差约 **0.0028%**，透射率绝对差不超过 **5.3e−6**。

拟合校准仍针对当前介质及灰色地面反照率 0.18。修改介质可以正常重算，但其最优分配和质量不由这批结果保证。有限段输运已验证，场景遮挡、froxel 缓存等体积光工程接入仍属于其他工作。

## 复现入口

```powershell
# 拟合的输入导出；out 要使用新目录或已有对应数据。
cargo run --release -p sky-atmosphere-lut --example hybrid_aux_audit_cpu -- --out out/hybrid_mapping_v3/optical_curves --export-curves-only
cargo run --release -p sky-atmosphere-lut --example skyview_allocation_cpu -- --out out/hybrid_mapping_v3/sky_curves --export-curves-only
python scripts/fit_hybrid_aux_cpu.py
python scripts/run_hybrid_mapping_v3.py selected_final
python scripts/run_hybrid_mapping_v3.py
python scripts/make_hybrid_mapping_sweeps.py
python scripts/run_hybrid_mapping_sweeps.py
cargo run --release -p sky-hybrid-atmosphere --example validate -- --out out/hybrid_mapping_v3/invariants.json
python scripts/summarize_hybrid_mapping_v3.py
```

消融脚本的 8-cone 控制组刻意固定，避免默认 preset 更新后污染历史比较；最终 12-cone 消融以 `final_` 开头。`legacy` 仍使用五 texel 的代数等价 Rayleigh 打包，其与旧可执行文件的直接积分结果最大场景 P99 差异约 0.0047%。所有诊断配置和运行日志随输出保存。
