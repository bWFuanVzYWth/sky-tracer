# 旧 UE 8 波长与当前 hybrid-4d 实测对比

2026-09-19。实现节点已提交为 `bc01cb9`。这里“旧实时”指 `unreal-8wave`，不是上一阶段较慢的 hybrid 配置，也不是从冻结参考派生 MS 的中间版 `four-wave`。本次只增加对比工具，没有调整两边的生产算法、波长或精度。

**当前方案在太阳变化时快约 2.2–2.8 倍，对冻结光谱参考的偏差明显更小；旧方案的优势是预计算快、常驻资源小，相机单独旋转时也略快。**

## 性能：实际 demo 的相同工作负载

RTX 4090 / Vulkan，512×384 输出，垂直 FOV 100°、俯仰 4°、海拔 0.2 km。正午太阳 85°、夕阳 0°、蓝调 −6°。每次 4 帧预热、64 帧计时，三个新旧交替轮次；表中为三个轮次中位数的中位数。每帧太阳变化 0.01°，确保 SkyView 重新生成。GPU timestamp 包含 experiment 渲染和展示 pass，不含初始化与回读。

|工作负载|旧 UE8|当前 hybrid-4d|变化|
|---|---:|---:|---:|
|正午太阳变化|0.529 ms|0.239 ms|快 2.22 倍|
|夕阳太阳变化|0.709 ms|0.269 ms|快 2.63 倍|
|蓝调太阳变化|0.713 ms|0.254 ms|快 2.81 倍|
|仅相机旋转|0.0092 ms|0.0123–0.0133 ms|旧方案略快|
|所有参数不变|0.0092 ms|0.0051 ms|当前复用屏幕输出|

同一轮次的最大 P95 有时显著高于中位数，旧方案存在约 1.2–1.4 ms 的尾部；保留完整原始统计，不把中位数当成最坏帧保证。测试没有覆盖 4K 性能，也没有把 512×384 的结果直接外推到 4K。

|资源／预计算|旧 UE8|当前 hybrid-4d|
|---|---:|---:|
|光谱通道|8（两组 vec4）|4|
|多重散射表示|两张 64² 各向同性表|各向异性 4D 源项，精确高空 Rayleigh 二次型|
|观察者 SkyView|256² RGBA16F RGB|256² RGBA32F，存 log Rec.2020|
|运行时视线积分|128 步|96 步|
|常驻 LUT／相位／SkyView 载荷|约 0.906 MiB|7.910 MiB|
|包括默认分配的空气透视纹理|约 1.406 MiB|同上，尚无 froxel 资源|
|介质变化时预计算|约 64.4 ms|约 393 ms|
|预计算峰值载荷|主要复用上述固定表|44.194 MiB|

旧资源按代码尺寸计算：两组 `256×64` 透射率和 `64×64` MS，均 RGBA16F；一张 `256²` RGBA16F SkyView；两组 `1024×3` RGBA32F 相位表，共 0.90625 MiB。构造函数还分配两张 `32³` RGBA16F 空气透视纹理，增加 0.5 MiB，天空 demo 不计算它们。小型 uniform、驱动开销和输出目标未计入；旧 demo 的 scene/post/depth 目标与新方案也不同，不将 LUT 载荷等同于整个应用显存。

旧预计算计时调用实际 `update_static_luts`，首轮后交替 0.18/0.181 反照率使缓存失效，六次完整 encode/submit/wait 中位数约 64.4 ms，计算透射率与 MS，不含 SkyView 和管线创建。当前 393 ms 来自上一轮六次交替实验的完整求解 wall time，同样不含管线／设备创建。它们属于相近的预计算范围，但不是逐 pass GPU 时间比较。当前更多时间花在保持各向异性的全场输运收敛上；介质不变时无需重复支付。

## 精度：冻结完整光谱参考

新增 `evaluate_unreal` 直接调用旧 renderer，按现有参考数据的九个相机、相同像素中心和视场输出线性 Rec.2020。当前使用已验证的 production SkyView 输出，包含运行时插值。两边仅关闭可见太阳盘，仍包含太阳附近散射。误差计算不使用展示曝光或 tone mapping。

以下只统计几何地平线上方的天空像素。每像素指标为 `100 × length(RGB−reference) / max(length(reference),1e−7)`，参考范数 >1e−8，取该图 P95。

|场景|旧 UE8 P95|当前 P95|
|---|---:|---:|
|正午太阳附近|6.50%|0.62%|
|正午地平线|8.53%|0.91%|
|夕阳|39.00%|2.17%|
|蓝调，向阳|50.22%|2.12%|
|蓝调，背阳|47.98%|1.37%|
|12 km 暮光|50.19%|5.46%|
|30 km 地影|94.71%|4.09%|

完整图像（含地面）的指标也保存在 JSON；它们与上表不同。例如夕阳完整图像 P95 为 50.83% / 2.06%。暗部 P95 相对误差会放大低亮度差异，不能直接当成整幅图的可见损失百分比；报告同时保存整体相对 L2 和平均亮度偏差。

这是**现有完整实现的比较**。旧方案和当前方案除了波长数，还存在分层介质表达、相位表、光学积分、MS 闭合及坐标映射等差异，不能把上表收益全部归因于四波长或某一项优化。旧波长仍为 410/440/480/520/540/580/610/670 nm，当前为 450/510/580/650 nm。

旧默认大气顶为 100 km，当前参考和 hybrid 为 120 km。额外只把旧大气顶改为 120 km 重测，前五个近地场景 P95 分别为 6.69%、8.79%、39.09%、50.35%、47.89%，主要结论不变；没有重新拟合旧介质和波长来“修好”它再比较。

冻结 41 波段 LUT 本身有输运与插值偏差，是当前工程参考而非物理真值。此表与上一轮“对加密四波长求解”的收敛误差口径不同，不能直接混用。

## PT 交叉检查

同一批 demo 的线性导出再与已有、修正过输运的 PT 图像比较。使用相同天空 mask，并排除直接太阳盘及可能被 PT 双线性插值污染的太阳盘 texel 覆盖范围。下表为整体相对 RGB L2，**不是上表的逐像素 P95**；视场也不同。

|场景|旧 UE8 对 PT|当前对 PT|
|---|---:|---:|
|正午|7.72%|1.21%|
|夕阳|19.99%|5.20%|
|蓝调|35.98%|20.09%|

蓝调 PT 噪声较强，两边都会被它抬高误差；当前对 PT 的平均亮度偏差约 −2.25%，旧方案约 −32.65%。因此本轮以无随机噪声的冻结光谱 LUT 对比为主，没有重新进行昂贵的 PT 烘焙，也没有把 20% 解释成当前确定性求解器的真实偏差。

## 高空与体积渲染边界

旧实现的 `view_radius_from_position` 会把相机钳制到大气顶下 1 m，SkyView 高度也会钳制，因此 108 km 与 400 km 场景不具备与当前方案相同的观察几何。诊断页展示它们用于说明能力限制，**不把它们纳入两方案的公平精度排名**。当前支持从太空进入大气，但对冻结参考在高空仍有已知差异，不能声称高空误差已全部解决。

旧方案已有 `32³` 空气透视接口；当前有经组合恒等式验证的四波长有限线段 L/T，可继续用于雾和体积光，但尚未接入完整 froxel、场景遮挡和 RGB 背景重建。当前在天空与传输精度上更完整，并不意味着旧空气透视功能已经被逐项替换。

## 复现和产物

```powershell
cargo build --release -p sky-atmosphere-lut --example evaluate_unreal
cargo build --release -p sky-realtime-demo
python scripts/compare_realtime_v1.py
python scripts/summarize_realtime_v1.py
python scripts/summarize_sky_comparison.py out/realtime_comparison_v1 --out out/realtime_comparison_v1/pt_summary.json
```

需要本机已有的冻结参考查询、production 输出与 PT 资产；脚本不会重烘焙它们。默认跳过已有结果，重测时使用新的输出目录或明确移走对应记录。

- `out/realtime_comparison_v1/summary.json`：九个相机的新旧误差及三个时段的计时。
- `out/realtime_comparison_v1/timings.json`：18 次 demo 测量及元数据。
- `out/realtime_comparison_v1/ue/runs.json`：旧方案初始化和有效相机高度。
- `out/realtime_comparison_v1/ue_top120/runs.json`：大气顶高度的单项检查。
- `out/realtime_comparison_v1/pt_summary.json`：PT 交叉检查，含原始亮度与误差。
- `out/realtime_comparison_v1/visual/index.html`：统一曝光的新旧天空、参考和误差图。

诊断 example 已 release 编译并实际 GPU 运行；所有导出值有限；18 组 demo 导出通过 absolute/signed 面板一致性检查。对比没有改变生产渲染器。
