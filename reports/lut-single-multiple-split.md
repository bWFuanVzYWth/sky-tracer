## 实际测试的结构

冻结参考 `out/lut_reference_v6` 只保存总辐亮度及总地面辐照度，没有单独保存每个散射阶次。模型指纹为 `18e1e068af347c04`。

在所需的原网格节点重新计算单次散射 S1，以及被视线透射衰减的地面边界 B，然后构造：

```
M(node, λ) = L_reference(node, λ) − S1(node, λ) − B(node, λ)
L(query)   = integrate_single(query) + interpolate(M, query) + B(query)
```

S1 使用与烘焙器一致的有限太阳盘 4×16 积分和真实分物种相位表。B 使用已存储的总地面辐照度。因此 M 包含大气中的间接散射，也包含地面反射后再次进入大气散射的贡献；地面边界另行计算。太阳直接圆盘不包含在本次比较中。

41 波段分别求出节点 M，再累加成线性 Rec.2020；查询处的 S1 也逐波段积分再转 Rec.2020。节点相减没有强制钳零：本次 29,554 个唯一节点 × 41 波段没有出现负光谱余量。RGB 仍允许带符号通道。

这里测试的是**有方向信息的四维多重散射辐亮度表**。Hillaire / UE 的小二维表保存各向同性近似下的多重散射贡献，并在视线行进中使用。借用其运行结构不代表必须接受相同的角度近似。本轮尚未测试二维各向同性源项版本。[论文](https://sebh.github.io/publications/egsr2020.pdf)，[作者实现](https://github.com/sebh/UnrealEngineSkyAtmosphere)。

## 容量与量化

多重散射候选网格为 **32×32×65×33**：高度、锥面观察位置、太阳角、相位角。高度使用包含关键剖面边界的原节点子集，其余两个角轴也是原参考的嵌套子集。保留原视线分支和插值方式。

3 通道 × 16 bit 的主表为 **13,178,880 B（13.18 MB）**。本次已经在查询所需的所有节点测试 **bfloat16** 量化，使用 f32 指数范围和 7 位尾数，逐节点解码后再插值；不是 TT 或联合低秩。三个通道可以紧密存入缓冲区，6 B/node 不等同于原生 `RGBA16F` 纹理容量，后者需要 8 B/node。本轮没有创建完整主表文件。

下表是保留 41 波段运行时计算的**拟议预算**，不是已验证资源：

|载荷|拟议配置|字节|
|---|---|---:|
|Rec.2020 多重散射主表|32×32×65×33×3×2|13,178,880|
|太阳/视线光学柱密度|128×1024×6×2|1,572,864|
|原相位表 + 有限太阳盘卷积相位表|2×41×4×1024×2|671,744|
|地面光谱辐照度|41×1024×2|83,968|
|剖面、系数、映射及对齐预留|—|131,072|
|合计|—|**15,638,528**|

六个柱密度对应空气、臭氧、四种气溶胶。当前模型的消光系数是这些固定高度剖面的光谱加权和，所以**先存六个路径积分，再按波长线性组合成光学深度**，在数学上能保持光谱消光结构。减小表分辨率及 16 位量化会另外引入误差，仍需特别验证夕阳透射、地影和掠射路径。这不是把光谱透射率直接平均成 RGB。

有限太阳盘卷积相位表可尝试减少远离地影时的太阳盘采样成本；半影区仍需要处理太阳盘上变化的遮挡及透射率。本轮实测全部使用原 64 个太阳盘样本，表中的这个优化尚未实现。

此预算不含屏幕帧缓冲、sky-view 或体积缓存。若改用 BC6H 压多重散射主表，理论上还可减少容量；其块误差及暗部误差未在本轮测量。

## 相同查询上的结果

从旧的 82,856 查询及新增困难区域中，每个区域确定性抽取 64 点，共 768 点；677 点的教师 RGB 向量长度 >1e-8，用于相对误差统计。下面是线性 Rec.2020 向量相对误差 **P95**。这不是此前大数据集 P99，也不是新的盲测集。

“同网格总表”和“拆分”都包含 bfloat16 节点量化。此表先用 256 步高精度单次积分，隔离主表表示的差异。联合压缩列重用已完成的查询结果，核对了逐点坐标。

|区域|同网格总辐亮度表|单次积分 + 多重表|此前 15.70 MB 联合压缩|
|---|---:|---:|---:|
|中午全景|1.60%|1.20%|1.56%|
|太阳 47°|0.75%|0.90%|1.65%|
|夕阳|1.90%|1.38%|0.96%|
|蓝调|1.39%|1.33%|0.93%|
|12 km|2.22%|1.35%|1.21%|
|30 km 地影|4.48%|1.98%|2.64%|
|120 km 边缘|8.09%|4.31%|0.36%|
|400 km 轨道|9.30%|16.67%|0.34%|
|中午光晕 0.27°–3°|3.87%|**0.074%**|0.57%|
|移动地影 26–36 km|18.30%|**3.28%**|2.50%|
|上层大气/太空压力样本|97.73%|25.30%|4.67%|
|全部有效样本|6.03%|4.06%|**1.46%**|

光晕的空间高频主要来自单次散射，拆出后相位节点从原来的 257 个降到 33 个仍能保持较低误差。蓝调以间接光为主，拆分不会自动消除多重散射的采样需求。

量化本身不是这里的主要损失：拆分 f32 与 bf16 的整体 P95 分别为 4.063% 和 4.062%。局部最大误差仍然必须保留在判断中：移动地影 12.40%，轨道 31.35%，上层/太空 34.32%。这些不能一概解释为不可见暗部；轨道的一个最大偏差点教师 RGB 长度约 7.78e-4。

## 实时积分不能简单减少均匀步数

实现了一个固定成本的步长映射：先把射线在最近切点处分成至多两段，再按距最低高度的 `log(1 + Δh / 0.25 km)` 分配区间，在每个距离区间中点积分。两段都覆盖，支持近地、地面方向、掠射及太空入口，不需要根据源项递归细分。

用同一光谱消光表和有限太阳盘，将步数变化单独与 **1024 均匀步** 比较；表中误差仍以总天空辐亮度归一化，不是除以单次散射。1024 步只是本次较高精度对照，不宣称严格收敛的真值。

|区域|均匀 64 步|高度映射 64 步|高度映射 32 步|
|---|---:|---:|---:|
|光晕|9.37%|**0.041%**|0.67%|
|蓝调|1.38%|0.15%|0.27%|
|移动地影|0.48%|1.19%|1.64%|
|400 km 轨道|0.35%|0.20%|1.21%|
|全部有效样本|7.65%|**0.14%**|0.66%|

高度映射对太阳光晕收益很大，但地影处均匀采样有时更好；统一压到 16 或 32 步还存在明显离群值。64 步高度映射的全组最大积分差异为 3.87%，32 步为 20.09%。因此需要按密度变化和地影边界分配采样，不能只按近地密度集中。

包含 64 步高度映射、bf16 主表的端到端结果：光晕 P95 **0.199%**，蓝调 **1.47%**，移动地影 **4.57%**，整体 **4.19%**。这比“只报告量化/主表误差”更接近最终行为，但仍未计入辅助表压缩或 GPU 精度差异。

本次执行的是 CPU 数值原型，没有 GPU 帧时数据。减少 TT 解码并不等于免费：直接照搬 41 波段 × 64 步 × 64 个太阳盘样本，每条完整天空射线约 168k 次太阳透射采样，仍然很贵。运行时应考虑太阳盘相位预卷积、半影专门采样，并将最终天空结果缓存到 sky-view；需要实测后才能判断性能优劣。

## 太空处为什么完整网格也不一致

另外保留 **80×32×193×257 完整网格** 做控制试验。轨道处拆分后的 P95 仍为 16.99%，而将原总辐亮度先转 RGB 再插值的 P95 仅约 0.0061%。因此这里并不是 33 相位节点或 bf16 导致的误差。

分解差异来源：

1. 查询处现场积分的 S1+B，与在原网格中插值得到的 S1+B 不同。轨道 P95 差异 **16.98%**，最大 **31.44%**。
2. 参考使用非线性 log/PCHIP 插值，不满足 `I(S1 + M) = I(S1) + I(M)`。轨道该项 P95 为 **0.154%**；移动地影可达 **1.26%**，最大 **6.35%**。
3. 轨道处 256→1024 步的单次积分差异 P95 仅 **0.0087%**，不足以解释第 1 项。

这定位了**参考单次散射的插值一致性问题**，但不能直接把这 31% 当作新方案对真实物理解的误差。冻结参考本身有偏，本轮没有新的 PT 或独立全输运解。后续需要单独核对该差异，避免把参考的插值偏差作为多重散射特征拟合回去。用户已停止参考重烘焙，本轮只记录诊断。

## 天空、视距雾和体积光

天空可以直接相加 `S1_rgb + M_rgb`，因为光谱到 RGB 的变换是线性的。这正是本次原型。

对于有限段 x→y，按波长有：

```
M_segment(λ) = M_boundary(x, λ) − T(x→y, λ) M_boundary(y, λ)
```

只存 Rec.2020 的 M 时，不能一般性地将它精确改写成三个 RGB 通道的乘法。短段相减也可能放大误差。因此 **13.18 MB 的 RGB 天空表还不是精确视距雾的完整方案**。

面向天空和体积统一用途，更接近 UE 结构的候选是保存离线参考导出的多重散射**局部源项** `J_ms(h, μs, view)`，实时沿有限段积分 `T · (J_single + J_ms)`。可先测二维各向同性基底，再按实际误差增加少量方向项，保留光谱或已验证的低维光谱表示。此方案尚未实现/量化，不能将本次四维边界辐亮度的结果算到它头上。局部遮挡和光束还需要运行时可见性处理。

当前建议：保留“实时单次 + 离线多重”作为候选主线，优先解决积分成本及多重源项表示；先比较方向残差、地影和有限段误差，再决定是否减少为纯二维。联合压缩资源继续作为已测基线。

## 复现与产物

```powershell
cargo run --release -p sky-atmosphere-lut --example probe_single_multi_cpu -- out/lut_reference_v6 --out out/lut_single_multi_rgb_warp --samples-per-region 64 --all-bands
python scripts/summarize_single_multi.py out/lut_single_multi_rgb_warp/probe.json
```

输出目录必须不存在，命令不会覆盖旧结果。`probe.json` 包含逐点数据、所有光谱源校验和、网格配置、有限太阳盘样本数和积分参数；`summary.json` 包含阈值 1e-8 / 1e-4 下的统计。保留约 0.7 MB 的稀疏 RGB 节点缓存以便后续 CPU 分析，不是完整生产资源。

实现：`crates/sky-atmosphere-lut/examples/probe_single_multi_cpu.rs`；汇总：`scripts/summarize_single_multi.py`。

几何步长测试覆盖地面、微小高度、切线两侧、上下半球和大气顶；测试及 `cargo clippy --example probe_single_multi_cpu --no-deps -- -D warnings` 通过。
