# 四波长 demo：固定多重散射源 + SkyView

后续更新：实时默认太阳积分已从 16 点收敛到固定 4 点，太阳高度变化约 1.1 ms。最终默认和简化误差见 [太阳模型与稳定框架](lut-four-wave-solar-framework.md)。下文保留原 16 点缓存实现的计时与精度记录。

2026-09-18。`four-wave` demo 已默认改用缓存渲染。冻结参考和四波长资源没有重烘焙；波长仍为 450、510、580、650 nm，默认 128 步、16 点有限太阳积分。上一版逐像素 SH 积分器保留为精度诊断入口。

## 更新依赖

之前虽然只读取一次磁盘资源，但每个屏幕像素的每个积分步都重新展开最多 153 个方向系数，相机转动也重做整幅积分。现在将这项工作移到固定源纹理初始化，并在显示前增加观察者 SkyView。

|事件|固定 MS 源|256×256 SkyView|屏幕投影|
|---|---|---|---|
|加载固定大气资源|展开一次|生成|更新|
|相机旋转、FOV、窗口大小|复用|复用|更新|
|太阳方位变化|复用|复用；旋转查询方向|更新|
|太阳高度、观察海拔变化|复用|更新|更新|
|积分步数、MS 调试开关变化|复用|更新|更新|
|曝光、显示模式变化|复用|复用|复用天空输出；只走显示 pass|
|画面参数完全不变|复用|复用|复用|

固定大气和地面反照率属于资源，改变它们需要换资源、重新创建渲染器。此处的 MS 初始化是已有 SH 数据的解码与重采样，不是重新求解多重散射。

## 数据与映射

0–35 km 保留原 40 个高度和 193 个太阳节点，将方向源展开为 24×8 方向纹理。方向使用太阳夹角 ν 和围绕太阳轴的锥角 β；ν 使用平滑混合 CDF，β 在 [0,π] 等距。纹理存归一化的四波长源项，均值单独保留 f32 并做 log 插值。运行时只需四个硬件双线性角度查询，再做高度/太阳插值。

35 km 起当前固定介质没有气溶胶，继续保留精确瑞利卷积所需的六个 SH 系数，无需铺满方向纹理。完整低空 SH 在第一次展开执行完后释放。

SkyView 存 f32 的 log Rec.2020，分为 96 行下半天空、96 行上半天空、64 行地面。地面边界两侧不跨支插值；地平线、太阳高度和大气薄边缘由平滑 CDF 集中采样。上下天空在水平面处分别保留端点，使观察者穿过 120 km 大气顶时，下半天空不会突然更换整个角度域。太空外缘的最后一格按弦长恢复趋零亮度，避免直接与 log(0) 插值造成薄边消失。

太阳圆盘在最终显示像素处单独计算，不放进 SkyView；光晕仍由 SkyView 插值。缓存不能保证任意放大倍率都没有插值误差。

|常驻资源|字节|
|---|---:|
|低空各向异性 MS，40×193×24×8×RGBA16F|11,857,920|
|高空六项 SH，含 35 km 接缝节点|379,824|
|均值、剖面、相位、地面、坐标等 f32|337,200|
|太阳光学厚度，384×1024×RGBA16F|3,145,728|
|SkyView，256×256×RGBA32F|1,048,576|
|合计|**16,769,248 B = 15.992 MiB = 16.769 MB**|

以上按 16 MiB 预算控制，包含 SkyView，不包含屏幕输出、PT 对照图、驱动/着色器对象等。磁盘资源仍为 12.687 MiB。首次展开额外临时数据约 9.92 MiB；初始化峰值约 25.92 MiB 加上上述未计入的对象。CLI 的 `--lut-budget-mib` 已按新的常驻量检查。正式路径不再分配屏幕尺寸的四波长透射率纹理；有限线段诊断仍使用原积分器。

## 实测速度

后续与旧 8 波长实现的同口径对照和分项计时见 [运行成本诊断](lut-four-wave-runtime-cost.md)：主要额外开销来自 16 点有限太阳积分，当前约 10 ms 不是各向异性 MS 的必要代价。

RTX 4090 / Vulkan，GPU timestamp；每项预热 4 帧、统计 12 帧。下表只计天空计算，不包括 UI / 呈现，也不包括一次初始化。

|分辨率|相机旋转|太阳方位变化|太阳高度变化|海拔变化|
|---|---:|---:|---:|---:|
|512×384|0.0092 ms|0.0082 ms|9.55 ms|9.52 ms|
|1920×1080|0.0287 ms|0.0287 ms|9.17 ms|9.16 ms|
|3840×2160|0.1638 ms|0.1464 ms|9.25 ms|9.39 ms|

同样使用 demo 的 512×384 光晕快照、包含显示 pass 进行前后对照：相机变化 **49.69 → 0.0154 ms**；太阳高度变化 **49.59 → 9.70 ms**；完全不变约 0.0061 ms。太阳/海拔更新仍有约 9–10 ms 开销，不能据此声称整个应用有上千 FPS。此前较小 SkyView 的约 5–6 ms 数据不代表最终 256×256 配置。

## 新增误差与检查

九张 192×96 视图，使用相同 128 步的上一版四波长逐像素 SH 解作基准。这些指标只衡量新增缓存误差，不是相对物理解或 41 波段参考的总误差。度量为线性 Rec.2020 向量相对误差，基准范数 >1e-8 的像素参与统计，分母下限 1e-7；太阳圆盘不参与该组对比。

|场景|仅固定 MS 纹理 P95|全部缓存 P95|全部缓存最大|
|---|---:|---:|---:|
|中午太阳附近|0.010%|0.324%|0.601%|
|中午地平线|0.147%|0.258%|0.318%|
|夕阳|0.744%|0.766%|1.544%|
|蓝调朝阳|0.947%|0.983%|1.717%|
|蓝调背阳|0.376%|0.391%|0.621%|
|12 km 暮光|0.852%|0.763%|2.638%|
|30 km 地影|0.571%|0.590%|3.139%|
|108 km 薄边|0.000%|0.386%|2.001%|
|400 km 轨道暮光|0.081%|0.314%|3.581%|

部分误差会抵消，不能将两层 P95 相加。放大误差图仍能看到 SkyView 网格的弧形残差；这不是“完全消除插值伪影”的证明。当前常规九视图的新增 P95 均小于 1%，孤立像素更高。

额外检查了 24 张 96×48 的参数扫描：

- 太阳高度 83°、87°、89°、89.9°、90°：新增 P95 0.145%–0.349%。
- 蓝调 −6.2° 至 −5.8°、间隔 0.05°：新增 P95 0.956%–1.005%；相邻帧缓存残差的变化 P95 ≤0.052%。
- 34.9、34.99、35、35.01、35.1 km：新增 P95 约 0.57%；跨 35 km 的两个 10 m 间隔，残差变化 P95 ≤0.007%。
- 119.9、119.99、120、120.01、120.1 km：新增 P95 0.568%–1.351%。119.99→120 km 的残差变化 P95 为 0.023%，120→120.01 km 为 0.518%。极薄外缘仍是后续精度重点。

通过 Naga 校验、Rust release 编译和十种实际 GPU 缓存失效检查。十种事件和完整性能测试中，MS 展开计数始终为 **1**；九场景 SkyView 仅更新 **7** 次，中午光晕/地平线以及蓝调朝阳/背阳各共用一张 SkyView。静态图与有限参数扫描不能代替所有连续运动的验收。

## 运行与产物

```powershell
cargo run --release -p sky-realtime-demo -- --experiment four-wave --lut-budget-mib 16
cargo run --release -p sky-atmosphere-lut --example validate_four_wave_cache
cargo run --release -p sky-atmosphere-lut --example benchmark_four_wave_cache
cargo run --release -p sky-atmosphere-lut --example validate_four_wave_gpu -- out/four_wave_source_v1 --queries out/wavelength_search_dataset_v1/queries.json --out out/four_wave_cache_v1/sky --steps 128 --mode sky
python scripts/summarize_four_wave_cache.py
```

诊断模式 `--mode reference` 使用原 SH 积分器，`--mode source` 使用固定 MS 纹理但仍逐像素积分，`--mode sky` 使用完整缓存。比较页位于 `out/four_wave_cache_v1/visual/index.html`，详细结果为同目录上一级的 `quality.json`、`sweeps.json`、`invalidation.json`、`benchmark.json`、`noon.json`。

四波长与冻结参考的既有误差、有限线段及高空参考偏差分析见 [原积分器报告](lut-four-wave-anisotropic.md)。本次不改变冻结求解器，也没有将二维 SkyView 当成体积雾的有限线段缓存；froxel 集成仍需单独完成。
